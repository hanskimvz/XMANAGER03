1

구매기안서 작성사전 · PR

무엇을 왜 구매할지 결재받기 위한 사전 문서입니다. 임시저장하면 PR-YYYY-NNNN 문서번호가 부여됩니다.

  • 품목 입력 방식(택1)
    • 품목표(BOM·상세단가) — 품목명/수량/단가/비고 + 합계 자동. BOM에서 선택 시 부품 링크(part_id)를 보존 → 발주서 자동생성에 사용. 엑셀 업로드도 가능.
    • 자유형식(일괄·간단) — 텍스트로 자유 작성 + 총액 직접 입력(예: “OO상사 잔금 일괄”, “소모품 외 6종”).
  • 거래처, 청구 금액(품목표면 합계 자동 / 자유형식이면 직접), 구매 구분(일반·과제·개발), 집행 조건, 예정 집행일, 사유
  • 발주서 자동 생성(선택) — 체크 + 공급업체 지정 시, 최종 승인되면 발주서가 자동 생성됨
  • ※ 시행자는 구매기안서엔 없습니다 — 실제 집행 담당은 지출결의서에서 지정합니다.
  • 결재선(결재자 1명 이상, 순서 지정) + 참조자(선택)
  • 첨부파일 — 임시저장 후 업로드(최대 200MB)
결과 상태
DRAFT (임시저장)
문서번호
PR-2026-0001 형식으로 즉시 채번
2

상신사전 · PR

작성자가 결재를 요청합니다. 상태가 DRAFT → IN_PROGRESS 로 바뀌고 1차 결재자에게 차례가 넘어갑니다.

검증
기안자 본인 · 결재선 1명 이상 · 필수 항목(자유형식이면 자유입력 내용) · 발주서 자동생성 선택 시 공급업체·BOM품목 필수
처리
1차 결재선 PENDING, 나머지 WAITING · 상신시각·본문 해시 기록
알림
1차 결재자 → 📄 결재 요청  ·  참조자 → 👀 참조 지정
3

결재 진행공통

결재자가 순서대로 승인합니다. 본인 차례(PENDING)이고 본인일 때만 처리할 수 있으며(관리자 예외 없음), 승인 시 도장이 찍힙니다.

  • 중간 승인 — 다음 결재자에게 차례가 넘어가고(다음 결재선 PENDING), 그 결재자에게 📄 결재 요청 알림
  • 결재대기함 — 이미 승인한 결재자도 최종 승인 전까지 목록에서 진행 상황을 볼 수 있고, 아직 결재할 건은 “내 차례” 뱃지로 구분
  • 반려 — 의견 필수. 상태 REJECTED, 기안자에게 ⛔ 알림 → 기안자가 수정 후 재상신 가능
  • 회수 — 기안자가 진행 중 문서를 회수하면 다시 DRAFT로, 이미 승인한 결재자에게 회수 알림
4

최종 승인사전 · PR

마지막 결재자가 승인하면 APPROVED 로 확정되고 완료 시각이 기록됩니다. 이 시점에 자동 후속 처리(발주서)가 이어집니다.

상태
APPROVED
알림
기안자 → ✅ 승인 완료
다음
실제 지출은 이어서 지출결의서(STEP 5~)로 결재받습니다
📦 발주서 자동 생성 (옵션 선택 시)
기안서에서 발주서 자동생성을 켰다면, 최종 승인 즉시 BOM에서 추가한 품목(part_id 보유)으로 발주서 1건이 임시저장(DRAFT) 상태로 자동 생성됩니다. 공급업체는 기안서에서 지정한 거래처, 자유입력 품목은 제외됩니다. 기안자에게 알림이 가고, 발주 관리에서 확인·확정합니다. (실패해도 결재 승인은 유지되는 best-effort)
5

지출결의서 작성사후 · PE

승인된 구매기안서에 이어 실제 지출(결제)을 결재받는 사후 문서입니다. 승인된 구매기안서 상세의 “후속: 지출결의서 작성”으로 진입하면 선행 문서가 자동 연결되고 내용이 미리 채워집니다.

  • 거래처, 품목(구매기안서 내용 프리필), 청구 금액, 결제방법(현금-선결제 / 익월결제 / 카드결제), 집행 요청 사유·시점, 실지급액, 비고
  • 시행자 지정(선택) — 승인 후 실제 집행(결제)을 맡을 사람 (시행자는 지출결의서에서만 지정)
  • 관련문서로 선행 구매기안서를 연결
결과 상태
DRAFT · 문서번호 PE-2026-0001
연계
지출결의서(사후)는 승인된 구매기안서(사전)에 연결되는 구조
6

지출결의서 상신 · 승인사후 · PE

상신과 결재 진행은 구매기안서와 동일합니다. 최종 승인 = 집행(결제) 완료로 처리됩니다.

상신 규칙
사후 문서라 원칙적으로 승인된 구매기안서 연결 전제. 단, 현재 정책은 미연결이어도 상신 통과(최종 결재자가 판단) — 연결했다면 그 구매기안서가 승인 완료 상태여야 함
상신 알림
1차 결재자 → 📄 결재 요청 · 참조자 → 👀 · 시행자 → 📦 시행 예정 지정
최종 승인
상태 APPROVED · 시행일(집행일 = 결제일) 자동 기록(입력값/미입력 시 당일) · 시행자 지정 시 시행 대기(PENDING) 전환
승인 알림
기안자 → ✅ 승인 완료 · 시행자 → 📦 “시행하세요”
🛠 관리자 정정
관리자는 관리 → 전자결재 → 결재 검색/정정 모달에서 시행일자·결제(집행)일을 사유 없이 즉시 수정할 수 있으며, 이 일자 수정은 정정 이력에 남지 않습니다(무흔적). 그 외 항목(제목/본문 등) 정정은 사유 필수 + 이력 기록.
7

시행 완료 (집행)지출결의서 시행자 지정 시

지출결의서에 시행자를 지정한 경우, 실제 집행(결제)을 마친 뒤 문서 상세에서 “시행 완료”를 눌러 마무리합니다.

조건
지정된 시행자 본인 · 상태 APPROVED · 시행 PENDING(시행전)
처리
시행 PENDING → DONE(시행후) · 시행일시 기록 · 기안자에게 ✅ 시행 완료 알림
관리
시행함 탭에서 시행전/시행후를 필터로 관리
