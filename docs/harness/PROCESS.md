# X-MANAGER 하네스 엔지니어링 프로세스

> **목적**: AI Agent 기반 역할 배분을 통한 개발 프로세스 정의
> **기획자**: YHS (의사결정권자)
> **적용 범위**: 개발 단계 이후 (기획은 기획자가 직접 수행)

---

## 1. 프로세스 전체 흐름

```
┌─────────────────────────────────────────────────────────────────────┐
│  Phase 0: 기획 (YHS 직접 수행)                                      │
│  ─ 요구사항 정의, 우선순위 결정, 방향성 설정                           │
└──────────────────────────┬──────────────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────────────┐
│  Phase 1: 설계 (Architect Agent)                                    │
│  ─ 요구사항 → 기술 설계서 변환                                       │
│  ─ DB 스키마, API 엔드포인트, 컴포넌트 구조 설계                      │
│  ─ 기존 코드에 미치는 영향 분석                                       │
│  ─ 산출물: 설계 명세 (task-tracker.md에 기록)                         │
└──────────────────────────┬──────────────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────────────┐
│  Phase 2: 구현 (Backend / Frontend Agent)                           │
│  ─ 설계서 기반 코드 구현                                             │
│  ─ Backend: FastAPI + SQLAlchemy + Alembic                          │
│  ─ Frontend: Vue 3 + TypeScript + Tailwind                          │
│  ─ 각 에이전트는 자기 영역만 수정                                     │
└──────────────────────────┬──────────────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────────────┐
│  Phase 3: 리뷰 (Reviewer Agents)                                    │
│  ─ 영업/수출 담당: "이 기능이 실무에서 쓸 수 있는가?"                  │
│  ─ 생산/품질 담당: "현장 워크플로우에 맞는가?"                         │
│  ─ 관리자(CxO): "ROI, 확장성, 전략적 가치가 있는가?"                  │
│  ─ 산출물: 피드백 리포트 (개선 제안 포함)                              │
└──────────────────────────┬──────────────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────────────┐
│  Phase 4: 반영 & 테스트                                             │
│  ─ 리뷰 피드백 중 채택 항목 반영 (기획자 승인 필요)                    │
│  ─ 기능 테스트 + 통합 테스트                                         │
│  ─ 완료 시 task-tracker.md 업데이트                                  │
└──────────────────────────┬──────────────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────────────┐
│  Phase 5: 완료                                                      │
│  ─ current-state.md 업데이트                                        │
│  ─ 커밋 & 배포                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

## 2. 에이전트 호출 규칙

### 2.1 호출 방식

각 에이전트는 해당 `.md` 파일을 읽어 페르소나를 로드한 뒤 응답합니다.

```
사용자: "@architect 이 기능 설계해줘"
→ Claude가 docs/harness/agents/architect.md를 읽고 아키텍트 관점에서 응답

사용자: "@sales-export 이 화면 리뷰해줘"
→ Claude가 docs/harness/reviewers/sales-export.md를 읽고 영업 담당자 관점에서 리뷰
```

### 2.2 에이전트 목록

| 호출명 | 파일 | 역할 | Phase |
|--------|------|------|-------|
| `@architect` | agents/architect.md | 시스템 설계, 영향 분석 | 1 |
| `@backend` | agents/backend.md | API, DB, 서비스 구현 | 2 |
| `@frontend` | agents/frontend.md | UI 컴포넌트, 화면 구현 | 2 |
| `@sales-export` | reviewers/sales-export.md | 영업/수출 실무 관점 리뷰 | 3 |
| `@production-qa` | reviewers/production-qa.md | 생산/품질 현장 관점 리뷰 | 3 |
| `@manager` | reviewers/manager-cxo.md | 경영진 관점 리뷰 | 3 |

### 2.3 기본 원칙

```
1. 기획자(YHS)가 최종 의사결정권을 가진다
2. 에이전트는 자기 역할 범위 내에서만 판단한다
3. 역할 간 충돌 시 기획자에게 판단을 요청한다
4. 리뷰어의 피드백은 "제안"이지 "지시"가 아니다
5. 모든 구현은 기존 코드 컨벤션(docs/claude.md)을 따른다
6. context/ 파일은 각 Phase 완료 시 업데이트한다
```

## 4. 빠른 시작 가이드

### 새 기능 개발 시

```
1. 요구사항을 한 문장으로 정리
2. "@architect 이 기능 설계해줘: {요구사항}"
3. 설계 확인 후 "@backend 구현해줘" / "@frontend 구현해줘"
4. 구현 완료 후 "@sales-export 리뷰해줘" (또는 해당 리뷰어)
5. 피드백 반영 후 커밋
```

### 버그 수정 시

```
1. 버그 현상 설명
2. "@backend 이 버그 수정해줘" (또는 @frontend)
3. 수정 후 바로 테스트 → 커밋 (리뷰 Phase 생략 가능)
```

### 전체 리뷰 시

```
1. "@sales-export 현재 {모듈} 전체 리뷰해줘"
2. "@production-qa 현재 {모듈} 전체 리뷰해줘"
3. "@manager 현재 {모듈} 전략적 가치 평가해줘"
4. 피드백 종합 후 기획자가 우선순위 결정
```
