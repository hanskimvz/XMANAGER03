> 이 문서를 X-Manager 리포에서 작업하는 Claude Code에게 그대로 주고 구현을 지시하세요.
> 같은 폴더의 문서들이 사양·데이터의 **단일 출처**입니다. 임의 추정 대신 이 문서를 따르세요.

## 🎯 목표

영업관리 **견적서(Q)** 에서, 영업이 입력한 **오더코드**(`HXB13AS-RJS-B-O2-S1-D55` 등)만으로 **단가가 자동 산출**되게 한다. 지금은 단가를 손으로 입력한다.

- 원가 소스는 **당분간 인터림 표(엑셀 추출 CSV)**, 나중에 BOM 원가로 **어댑터만 교체**.
- 계산은 **백엔드가 권위**를 갖는다(현재는 프론트 입력을 신뢰 → 서버 산출로).

## ⚠️ 반드시 지킬 핵심 원칙 (틀리기 쉬움)

1. **마진 공식:** `판매가 = 원가 / (1 − 마진율)`. **`원가 × (1 + 마진율)` 아님!** (현재 프론트 `SalesDocumentFormModal.vue` autoFillItem는 후자 방식 → 반드시 전자로 교체.)
2. **마진 = 모델 C:** `적용마진 = clamp(채널기준(채널) + 고객조정(고객), 6ch하한56)`. 채널기준 2ch60/4ch55/6ch56. 고객측은 **① 단일 델타(±%p)**. → **백엔드 중앙 함수 `resolve_margin(customer, channel)` 한 곳**에 집중(추후 고객×채널 확장의 유일 교체점).
3. **통화:** 옵션 B(통화별 표 유지, 엑셀과 100% 일치). KRW·USD 표 값 그대로 사용.
4. **국내(원화) 프리미엄:** 합계 × **1.3** 후 ₩1,000 올림. USD는 프리미엄 없이 $1 올림.
5. **환율:** 시스템 설정값 **기본 1,100**(관리자만 변경, 일반 견적 UI 미노출). `app_setting`/`settings`에 저장.
6. **가격 인상률:** 노후가 보정은 **비율(%)로만, 상수 가산 금지**. **품목별** 인상률(+전역 기본), 관리자 설정. `조정원가 = 기준원가 × (1+인상률/100)`.
7. **가격 결정 우선순위:** ① 거래처 **합의가**(있으면 계산 없이 그대로) → ② 계산. 합의가는 **거래처(business_partner)에 연결 저장**.
8. **부츠(D55/S20/S09) 무관**, **엔드페이스 전종류 채널수×1,500**, **SA면 커넥터B=커넥터A**.
9. **교체 이음새:** 원가 조회를 인터페이스로 격리 → `get_connector_cost(size,form,core,mode)`. Phase1=인터림표, Phase2=`price_service.calculate_bom_cost`.

## 🔩 기존 코드 접점 (이미 있는 것 — 재사용)

- 오더코드 토큰화: `backend/app/api/v1/product_description_code.py` `compose()` (PRODUCT/TYPE/MATERIAL/CHANNEL/FIBER/CABLE). **이 토큰 분류 재사용**하되 원가 매핑 추가.
- 원가엔진(Phase2용): `backend/app/services/price_service.py` `calculate_bom_cost` / `get_part_unit_cost`.
- 고객 마진: `backend/app/models/business_partner.py` `default_margin_rate` → **델타로 재해석하거나 `margin_adjustment` 신설**.
- 견적 라인: `backend/app/models/sales_document.py` `SalesDocumentItem(product_code, unit_price, amount)`. 백엔드 create/update는 현재 합산만(`sales_document_service.py`).
- 견적 폼(자동가격 부분구현): `frontend/src/components/sales/SalesDocumentFormModal.vue` (`autoFillItem`, `applyMarginToAll`, `marginRate`).
- 환율: `ExchangeRate` 모델 / `app_setting`.
- 참고 API: `GET /sales-documents/last-price/{customer}/{product}` (과거가).

## 🧭 구현 단계 (권장 순서)

**1) 데이터/설정 레이어**
- 인터림 표 시드: 커넥터원가(A), 케이블미터당(B), 조립비(C), 커넥터B(D), SUS쉘(옵션). CSV → seed/설정 테이블.
- 설정값: 환율(기본1100), 채널기준마진(2/4/6), 국내프리미엄(1.3), 품목별 인상률.
- 거래처 합의가: `business_partner` 연결 서브테이블(품목·단가·통화·유효기간).

**2) 오더코드 파서** — `compose` 기반으로 (size, form, core→채널수, mode(S/M), SA, 재질) 추출. 실패 시 경고+수기허용.

**3) 원가 소스 어댑터** — `get_connector_cost(size,form,core,mode)` (Phase1: A표 조회 + 품목 인상률 적용). 인터페이스로 격리.

**4) 중앙 마진 함수** — `resolve_margin(customer, channel)` (모델 C).

**5) 견적 계산 서비스 + 엔드포인트** — 신규 `POST /sales-documents/suggest-price`:
   입력 `{order_code, length_m, quantity, customer_id, currency}` → 출력 `{unit_price, breakdown{커넥터A,커넥터B,케이블,조립비,옵션델타}, applied{마진,환율,프리미엄}, warnings}`.
   내부: **가격결정 우선순위**(합의가→계산) → 조립체 계산(§6) → 통화·프리미엄. **백엔드 권위.**

**6) 프론트 연결** — 견적 폼의 클라이언트 계산(`autoFillItem` L~1437 등)을 이 엔드포인트 호출로 교체. breakdown·경고 표시. 값은 수정 가능(오버라이드 허용)하되 기본은 서버값.

**7) (후순위) 과거가 백필 + 합의가 입력 UI** — `가격이력_마스터_2025_2026.xlsx`를 가격이력으로 임포트, 거래처 화면에 합의가 리스트 입력.

## ✅ 산출 검증 (반드시 통과 — 원화, 채널마진=엑셀기준 2/4ch 0.6·6ch 0.56)

| 오더코드 | 미터 | 기대 단가(₩) |
|---|---|---|
| HXB13AS-RJS-B-O2-S1-S20 | 2 | 357,000 |
| HXB13AS-PSD-B-O2-S1-D55 | 3 | 367,000 |
| HXB15AS-RJS-B-O4-M3-S20 | 2 | 476,000 |
| HXB15AS-PSD-B-O4-M3-D55 | 3 | 481,000 |

**컴포넌트 단위 테스트(1번 케이스, margin 0.6):**
`커넥터A=77,602.5/(1-0.6)=194,006.25` + `커넥터B=2×1,500=3,000` + `케이블=2×2,800=5,600` + `조립비=72,000(2ch·1단)` = `합계 274,606.25` → `×1.3=356,988.13` → `ROUNDUP(-3)=357,000`.

> 참고: 모델 C 기본(4ch=55)으로 계산하면 4ch 케이스는 440,000·445,000이 정상(마진 정책 차이, 오류 아님). 마진율을 config로 두어 둘 다 재현 가능해야 함.
