## 1. 목적 · 범위

**목적:** 영업이 입력한 **오더코드**만으로 견적 단가가 자동 산출되게 한다. 부품/BOM 원가 데이터 입력을 기다리지 않고, **견적 폴더 엑셀의 표·규칙을 인터림 원가 소스**로 써서 지금 바로 동작시킨다.

**Phase 1 원칙:** 현재 엑셀이 내는 숫자를 **그대로 재현**한다(오늘 나가는 견적과 일치). 마진 통일·×1.3 대체 등 "개선"은 로직을 드러낸 뒤 별도 단계에서.

**Phase 1 범위 밖(추후):** 리프부품 단위원가·BOM 롤업, 재고 연동, 8/10/12/16채널·하이브리드·믹스모드(별도 파일 로직), 커넥터 단품/케이블 단독 견적.

## 2. 전체 파이프라인

```
오더코드  HXB13AS-RJS-B-O2-S1-D55(-LC)   +  미터수, 수량, 고객사
   │ ① 파싱 → 토큰(사이즈·형태·재질·채널·모드·부츠·엔드페이스·SA)
   ▼
② 원가 조회 + 인상률(비율) 적용  🔀[교체 이음새]   Phase1: 인터림 Price List 표 / Phase2: BOM 롤업
   ▼
③ 조립체 계산 = 커넥터A + 커넥터B + 케이블 + 조립비 + 옵션델타(+기타)
   ▼
④ 마진 · 통화 · 국내 프리미엄
   ▼
⑤ 단가 → 견적서 라인아이템
```

바뀌는 건 ②뿐. ①③④⑤는 Phase 1·2 공통.

## 2.1 가격 결정 우선순위 (중요)

견적 단가는 **두 경로**가 있고, 엔진은 위에서부터 적용한다:

1. **고객 합의가 (계약 price list)** — 고객사와 이미 합의된 품목별 단가가 있으면 **계산 없이 그대로 사용**(조립체계산·마진·프리미엄 건너뜀). **최우선.**
2. **계산 경로 (§2 파이프라인)** — 합의가가 없을 때만 오더코드로 산출.

- (참고) 과거 견적가 `get_last_quoted_price`는 계산 경로의 보조·검증용(직전가 대비 경고).
- 🔩 **X-Manager 저장(확정):** 합의가는 **거래처(business_partner)에 연결된 품목별 합의단가 리스트**로 저장하고, 견적 시 그 거래처에서 불러온다. 기존 거래처-연락처/배송지 서브테이블과 동일 패턴. 필드: 품목(오더코드/품번)·합의단가·통화·유효기간(선택). (`is_protected` 전속계약과는 별개 구조.)

## 4. 오더코드 문법 (파싱 규칙)

예: `HXB13AS-RJS-B-O2-S1-D55-LC-002/30`

| 세그먼트 | 의미 | 값(예) | 비고 |
|---|---|---|---|
| PRODUCT | 사이즈/시리즈 | HXB11 / 13 / 15 | `AS`=조립표시 → 제거 |
| FORM | 커넥터 형태 | PSD(Plug) / RJS·RJN·RJL(Recep Jam) / RQS·RQN·RQL(Recep Flange) | S=Std, L=LowProfile, N=Std복제 |
| MATERIAL | 재질 | **B**=Al 블랙아노다이즈 / **S**=SUS | 원가에 영향 → §7 옵션델타 |
| CHANNEL | 채널수 | O2 / O4 / O6 / O8 | 숫자 = RIGHT 1자리 |
| MODE(FIBER) | 모드 | S1(SM) / M3(MM) 등 | 모드 = 앞글자 S/M |
| BOOT(CABLE) | 부츠/케이블경 | D55 / S20 / S09 … | **가격 무관** — 셋 다 동일단가, 계산에서 무시 |

> ❓ 지금은 자유텍스트라 오타·형식오류 가능 → 파싱 실패 시 처리(경고 후 수기 단가 허용) 규칙 필요.

## 5. 인터림 참조 데이터 (Phase 1 원가 소스)

견적 폴더 엑셀을 아래 **구조화 표**로 추출해 X-Manager가 참조(시드/설정테이블). 값은 KRW 기준.

| 채널 | 1단(₩/$) | 2단(₩/$) |

## 6. 계산 규칙 (③ 조립체)

구성요소는 **통화별 표**에서 조회(옵션 B 확정 — 엑셀과 100% 일치, 추후 KRW 단일 정규화 예정). 마진은 **판매가 대비**(엑셀 방식).

> ⚠️ **가격 인상률(비율) 원칙:** 인터림 원가·과거단가가 노후하여 가격이 올랐으면 **비율(%)로만** 상향한다. `조정원가 = 기준원가 × (1 + 인상률/100)`. **상수(예: +30,000원) 가산은 금지**(과거 임의 상수 인상 = 문제 ①의 원인). 인상률은 관리자 설정값(전역 기본 + 품목별 선택). 아래 커넥터원가는 이 조정원가를 의미.

```
커넥터A(판매)  = 커넥터원가(A표) / (1 − 마진율)         # 마진: 채널·고객별
커넥터B        = SA면 커넥터A(양단 동일 커넥터), 아니면 채널수 × 1,500   # 엔드페이스 전 종류 동일(LC·SC·APC·FC…)
케이블         = length_m × 미터당단가(B표: 모드,채널)
조립비         = 조립비표(C표: 채널, 단수)               # SA → 2단, 아니면 1단  ❓확정
옵션델타       = Σ(비표준 옵션 가감)  (SUS 등, §7)
기타           = 수기 입력(선택)
─────────────────────────────────────────
합계₩ = 커넥터A + 커넥터B + 케이블 + 조립비 + 옵션델타 + 기타
```

> ⚠️ **마진 계산 방식 주의:** 엑셀 = `원가/(1−마진)`(마진=판매가의 %). **X-Manager 현재 프론트는 `원가×(1+마진)`(원가 대비 마크업)** 으로 다름(`SalesDocumentFormModal.vue` autoFillItem). 같은 60%라도 결과가 크게 달라짐(÷0.4=2.5배 vs ×1.6). → **엑셀 방식으로 통일** 필요. 🔩

## 7. 마진 · 통화 · 국내 프리미엄 (④)

**마진율 결정 — 모델 C(조합) 확정:**
```
적용마진율(%) = clamp( 채널기준(채널) + 고객조정(고객) , 하한(채널) )
판매가        = 원가 / (1 − 적용마진율/100)
```
- **채널기준(base):** 2ch 60 / 4ch 55 / 6ch 56 (8·10·12·16ch 별도 파일 로직)
- **고객조정(delta, %p):** 고객별 가감(신규 +, 대형단골 −; 기본 0)
- **하한:** 6ch ≥ 56 (무조건 56%부터)
- **고객측 = ① 단일 델타 확정** (거래처당 조정값 ±%p 하나). 고객×채널 override(②)는 추후 순증 확장.
- 🔩 X-Manager 연동: (a) **채널기준마진 config 신설**, (b) 기존 `default_margin_rate`(전체값)를 **델타로 재해석하거나 별도 `margin_adjustment` 필드 신설**, (c) **마진 해석을 백엔드 중앙 함수 `resolve_margin(customer, channel)` 하나로 집중**(현재는 프론트 `SalesDocumentFormModal`에서만 계산). → ②로 확장 시 이 함수 내부 + 오버라이드 표만 추가, 호출부·파이프라인 불변(비파괴).

**통화·프리미엄 최종화:**
```
USD 견적:  unit_price = ROUNDUP( 합계₩ / 환율 , 0 )          # 프리미엄 없음
KRW 견적:  unit_price = ROUNDUP( 합계₩ × 국내프리미엄 , −3 )  # 프리미엄=1.3(유지 확정), ₩1,000 올림
```
- 🔩 환율(확정): **시스템 설정값, 기본 1,100 고정.** 관리자만 필요시 변경, **일반 견적 화면엔 미노출**(매번 입력 X), 실시간 자동갱신 아님. X-Manager `app_setting`/`settings` 설정에 저장(단일 상수).
- **국내 프리미엄 = 명시 파라미터**로 노출(숨은 ×1.3 아님). 값·적용조건(국내 소량·단발) 규칙화 → §11.

**옵션 델타(SUS 등):** 재질이 SUS면 커넥터A 원가를 SUS 원가로 대체(또는 +델타). Phase 1은 **명시 델타 항목**으로 처리(최종가·기타에 우겨넣지 않음).
- **원가 위치(확인됨):** `견적/신제품 임시/스테인레스 재질 견적/SUS 커넥터 견적 - 0730.xlsx`
  - `220516_HXB13/15 원가가격` 시트 = **오더코드별 쉘원가표**, 재질 `B`(Al)/`S3`(SUS303)/`S6`(SUS316) 나란히. 예 HXB13-PSD B=21,310 / S3=32,640 / S6=55,140.
  - `신규 원가계산` = 최신 SUS316 빌드업(마진 0.56~0.58). `HXB13_부품 원가가격` = 부품 BOM 원가(Phase2 자산).
  - 최신 가공비: `원가 확인용 참고자료 모음/스테인레스 쉘 가공비/*.pdf`(2025). 220516 시트는 2022.05 기준(구버전 주의).
- **규칙 메모:** 간이식 "SUS 쉘 ≈ Al 쉘 × 3배". SUS는 마진 더 높게(56~58%, 소량 편차 큼).
- **재질 토큰 처리(확정):** 오더코드는 `S`로 유지(파싱에서 S3/S6로 분해하지 않음). SUS는 **우리가 구매하거나 고객 요청 시에만** 해당 → **견적 산출 시 실제 구매한 SUS 재질/비용을 옵션으로 선택**해 델타 적용. 자동 판별 규칙 불필요. (구매 SUS 재질·단가 목록을 옵션 선택지로 제공)

## 8. 🔀 Phase 2 전환 이음새 (BOM 교체)

②원가조회를 **인터페이스 하나**로 격리한다. 나머지 로직 불변.

```
CostSource.getConnectorCost(size, form, channel, mode, material) -> { cost_krw }

Phase 1:  InterimPriceListSource   = §5(A) 표 조회
Phase 2:  BomCostSource            = 오더코드 → Part 해석 → price_service.calculate_bom_cost()
```
- 🔀 Phase 2에서 추가로 필요한 것: **오더코드 ↔ Part 매핑**(현재 없음 — 별개 코드체계, §"핵심 문제"). 재질 B→A6 / S→S4·S6 등 토큰↔Part 매핑 or 라인아이템 구조화.
- 케이블·조립비도 동일 패턴으로 Phase 2에서 BOM/공정 원가로 교체 가능.

## 9. 🔩 X-Manager 연동 지점

**재사용(있음):**
- 오더코드 토큰화: `product_description_code.compose` (`api/v1/product_description_code.py`)
- 원가엔진(Phase 2): `price_service.calculate_bom_cost` / `get_part_unit_cost`, API `GET /prices/parts/{id}/bom-cost`
- 고객 마진: `business_partner.default_margin_rate`
- 견적 라인: `sales_document.SalesDocumentItem(product_code, unit_price, amount)`
- 환율: `ExchangeRate`

**신규(만들 것):**
- **인터림 견적 계산 서비스/엔드포인트** (제안 `POST /sales-documents/suggest-price`): `order_code + length_m + qty + customer_id + currency` → `unit_price + breakdown`. **백엔드 권위 계산**(현재는 프론트 입력 신뢰).
- **중앙 마진 함수 `resolve_margin(customer, channel)`** — 모델 C 계산을 여기 한 곳에 집중. ②(고객×채널) 확장의 유일한 교체점.
- **채널기준마진 config** + 고객 델타 필드.
- **거래처(business_partner) 연결 합의가 리스트**(품목→단가·통화·유효기간) — 거래처-연락처/배송지 서브테이블 패턴. + **가격 결정 우선순위**(합의가→계산, §2.1). `is_protected`(전속계약)과 별개.
- **품목별 가격 인상률 config**.
- §5 인터림 표를 담을 **설정/시드 데이터**.

**고칠 갭:**
- 마진 방식 통일(§6 ⚠️), KRW→통화 환율 미적용 갭(`SalesDocumentFormModal.vue` ≈L1434-1438), 오더코드→Part 퍼지 키워드검색 → 파싱 토큰 기반으로.

## 11. 결정 현황
**✅ 확정**
- **국내 프리미엄:** ×1.3 **유지**.
- **마진 모델:** **C(조합)** = 채널기준 + 고객조정, 6ch 하한 56% (§7).
- **마진 고객측:** **① 단일 델타** + **백엔드 중앙 `resolve_margin` 함수**. ②(고객×채널)는 추후 순증 확장.
- **환율:** 시스템 설정값 **기본 1,100 고정**, 관리자만 필요시 변경(일반 UI 미노출).
- **SUS 재질:** 오더코드 `S` 유지, **견적 시 구매 SUS 재질·비용을 옵션 선택**(자동판별 X).
- **통화 정규화:** **옵션 B(통화별 표 유지)** — 엑셀과 100% 일치. 추후 KRW 단일 정규화로 업데이트.
- **커넥터 단품:** **Phase 1 포함** — Price List 조회 또는 과거 견적 참조(커넥터A만).
- **가격 인상률:** 노후가 보정은 **비율(%)로만, 상수 금지**(§6·§5-G).
- **부츠(D55/S20/S09):** **가격 무관** — 동일단가, 계산에서 무시.
- **엔드페이스:** 커넥터B로 반영. SA→커넥터A(양단 동일), 그 외 **전 종류(LC·SC·APC·FC…) 채널수×1,500 동일**.
- **가격 인상률 범위:** **품목별**(+ 전역 기본).
- **고객 합의가 우선 경로:** 합의 price list 있으면 계산 없이 직접 사용(§2.1). **거래처(business_partner)에 연결 저장·불러오기.**

**❓ 아직 열린 것**
- (규칙 레벨 결정 완료) 구현 세부만 남음: 합의가 입력 UI(엑셀 업로드 vs 화면), 유효기간 운용, 인상률 config 위치 등은 구현 요청서 단계에서.
