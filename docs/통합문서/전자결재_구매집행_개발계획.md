# 구매 집행 절차 개선 — 개발계획 (구매기안서 → 지출결의서 연결형)

> 작성 2026-06-22. 결정: **2문서 연결형**(사용자 확정). 출장신청서→출장정산서와 동일한 PRE→POST 프레임 재사용.
> 상태: ~~**계획**(구현 전)~~ → 🟡 **구현 완료(v0.46~0.48)**. 이 문서는 착수 전 계획본이며, 실제 구현(품목 표·시행일·집행담당 지정·연결완화 등)·결정사항은 [전자결재_시스템통합_수정사항.md](전자결재_시스템통합_수정사항.md) 업데이트 로그(v0.46.0/0.46.1/0.48.0/0.49.0)를 정본으로 본다. 관련: `전자결재_시스템통합_수정사항.md`.

## 1. 목표 흐름
| 단계 | 문서 | 기안자 | 결재자 | 의미 |
|---|---|---|---|---|
| ① | **구매기안서(PURCHASE, PRE)** | 구매담당 | 대표 | 구매 승인 + 결제방법/집행조건 명시 |
| ② | **지출결의서(DISBURSEMENT, POST→PURCHASE)** | 구매담당 | 집행담당(+선택 대표) | 집행 요청 → 승인=집행완료(시행일 기록) |

- 한 구매기안서에 **지출결의서 여러 건**(분할 집행) 가능 — 모델이 이미 다건 연결 허용.
- 가시성: 푸시 없음 → **문서함+배지** 기반. 구매담당=②기안자라 자기 기안함에서 집행완료 확인. ①상세에 "연결 지출결의서: 집행완료(날짜)" 표시.

## 2. 데이터/양식 변경

### 2.1 구매기안서(PURCHASE) — phase NONE→PRE, 필드 추가
기존 fields: item, quantity, unit_price, vendor, reason. 추가:
- `payment_method` select: 현금-선결제 / 익월결제 / 카드결제
- `execution_condition` select: 검수완료 후 / 선집행 / 익월 / 지정일
- `planned_exec_date` date(선택, 지정일일 때 권장)
- `amount` number(합계, prefill 매개) — 또는 quantity×unit_price 계산값 저장

### 2.2 지출결의서(DISBURSEMENT) — 신규 POST 양식, linked_form_code=PURCHASE
- prefill 위해 PURCHASE와 **키 정렬**: `vendor`, `amount`, `payment_method` 동일 키 → 기존 `prefillFromPredecessor` 자동 복사.
- 고유 필드: `request_note`(집행요청 사유/시점), **`exec_date`(시행일=집행일)**, `actual_amount`(실집행액, 기본=amount), `note`.
- 문서번호 접두어: 신규 `DISBURSEMENT→PE`(또는 EX) `_DOC_PREFIX`에 추가.

### 2.3 마이그레이션 (v0.45.x)
- `UPDATE approval_forms SET phase='PRE' WHERE code='PURCHASE'` + fields_schema 갱신.
- `INSERT` DISBURSEMENT 양식(phase POST, linked PURCHASE, fields_schema, sort_order).
- 기존 PURCHASE 문서(phase NONE 시절 작성분)는 영향 없음(연결은 신규부터).

## 3. 시행일(집행일) 캡처 — 승인 시 입력 [권장]
"결재 시 시행일 입력" 요구 → 지출결의서 **승인 단계에서 집행담당이 `exec_date` 입력**, 승인=집행완료.
- 백엔드: approve 액션에 **선택적 구조화 입력**(`exec_date`)을 허용하도록 소폭 확장 — 해당 문서의 form_data.exec_date에 기록(또는 전용 컬럼). 다른 양식엔 영향 없음(지출결의서에서만 노출).
- 대안(확장 최소): `exec_date`를 기안자(구매담당)가 "희망 집행일"로 입력, 실제 집행 시각=승인 acted_at. → 백엔드 무변경이지만 "집행자가 입력"은 아님.
- **결정 D-구매1**: 승인 시 입력(권장) vs 희망일+승인시각.

## 4. 프론트
- 구매기안서 작성: 결제방법/집행조건/예정일 입력 UI(select/date).
- 지출결의서: PRE에서 [후속 작성]으로 진입 → 자동 prefill. 결재선 기본=집행담당.
- ①구매기안 상세: **연결된 지출결의서 목록·상태(집행완료/대기) + 시행일** 표시(연결 역방향 조회).
- 집행담당 승인 화면: 시행일 입력란(§3 권장안 채택 시).

## 5. 권한/역할
- 집행담당 = 경영지원(기존 STAFF_MGMT/FULL). 별도 권한 추가 불필요(approval:approve로 충분). 필요 시 `approval` 모듈 세분화는 추후.

## 6. 작업 분해
1. 마이그레이션(PURCHASE→PRE+필드, DISBURSEMENT 신규, 문서번호 접두어).
2. (D-구매1 채택 시) approve 확장: exec_date 선택 입력.
3. 프론트: 구매기안 필드 + 지출결의서 후속작성 + 상세 연결상태 표시 + (승인 시 시행일).
4. 검증: 구매기안 승인→지출결의 후속작성(prefill)→집행담당 승인(시행일)→구매담당 확인, TestClient/E2E.

## 7. 확정 필요 결정
- **D-구매1**: 시행일 입력 방식(승인 시 입력[권장] / 희망일+승인시각).
- **D-구매2**: 지출결의서 결재선 기본 = 집행담당만 / 집행담당+대표.
- **D-구매3**: 결제방법·집행조건 select 항목 확정(위 기본안 사용 여부).
