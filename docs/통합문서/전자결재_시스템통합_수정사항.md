## 8. 설정 / 보안 (운영 적용 시 필수) — **2026-06-22 코드 해소 완료**

상세·근거: `전자결재_통합_유의사항.md`. 아래는 실제 코드 확인 결과.

> ⚠️ **운영 서버는 인터넷 공개(public)** — 내부망 전용 아님. 따라서 **HTTPS(TLS) 필수**(평문 시 토큰·결재내용 도청), CORS 도메인 제한은 **권장**, 무인증 노출 최소화 위해 배포 직후 `observe`. → 배포 후 처리 항목은 §13.2.

| 항목 | 상태 | 조치 내용 |
|---|---|---|
| ③ SECRET_KEY 하드코딩 | ✅ 해소 | `auth.py`가 `settings.SECRET_KEY` 사용 + 기동 가드 |
| ② admin 무인증 | ✅ 해소 | `admin.py` 라우터 `require_admin` |
| ④ 전역 traceback 응답 노출 | ✅ 해소 | `main.py` 핸들러 — 응답에서 traceback 제거(서버 로그에만), 운영=일반메시지 |
| ⑥ DEBUG 로깅 고정 | ✅ 해소 | `main.py` `_IS_PROD` 분기 → 운영 INFO / 개발 DEBUG |
| ⑤ CORS 전체 허용 | ✅ 가드 | 운영에서 `*`면 기동 경고 로그. `.env.production`에 `BACKEND_CORS_ORIGINS` 항목 추가(도메인 제한 안내) |
| 🔴 `.env.production` SECRET_KEY | ✅ 해소 | **강력 난수 64자로 교체** + `_check_secret_key`가 placeholder/짧은키 **기동 차단**(이제 잡힘) |

- ⚠️ **HTTPS(TLS) 필수**(인터넷 공개) + **CORS 도메인 제한 권장**: `.env.production`의 `BACKEND_CORS_ORIGINS=["*"]`를 실제 접속 origin으로 좁히면 경고 사라짐. 정확한 origin은 배포 후 실주소 확인 필요 → §13.2.
- ⚠️ SECRET_KEY 교체 시 **기존 발급 토큰 전부 무효**(전원 재로그인) — 배포 공지.

- **역할**: ADMIN / USER + RBAC 역할(EMPLOYEE/표준4종). `require_auth`(로그인) / `require_admin`(ADMIN). 관리 화면은 **메뉴 숨김 + 라우터 가드 + 백엔드 require_admin** 3중 보호.
- **문서 단위**: 전자결재 문서는 기안자/결재선/참조자/ADMIN만 열람, 결재는 차례 본인만.
- 부서/직급 기반(행 단위) 접근제어는 **미도입**(계획서 §14, 별도 Phase).

### 11.2 교차 모듈 의존성 — enforce 전 필독 (2026-06-22)
- enforce는 **데이터 연결성(FK·조인·저장)을 깨지 않음**(라우터 진입만 가드). 그러나 **한 화면이 여러 모듈 API를 호출**하므로(BOM→part/code/price, 영업→sales_activity/partner/part/code 등), 그 화면을 쓰는 역할에 **옆 모듈 읽기권한이 없으면 화면 일부가 403**.
- `code:view`·`price:view`·`partner:view`는 사실상 **공통 전이적 읽기** 권한 → 거의 전 역할에 부여 권장.
- **확정 방법**: observe 로그 실측(B). 상세 절차/예측 갭표: `전자결재_RBAC_하이브리드_개발계획.md` §17~§18.

### 11.3 전자결재 우선 도입 모델 — coarse 2역할 (2026-06-22 확정·검증)
전 직원에게 계정을 주되 **비영업 직원은 전자결재만** 쓰게 하는 단계적 도입. 세분권한은 나중에 한 모듈씩 좁힘(가산적).

| 역할(code) | 권한 | enforce 시 동작 |
|---|---|---|
| **APPROVAL_ONLY** (전자결재 전용) | `dashboard:view`, `approval:view/create/approve` | 전자결재·홈만. 부품/발주/영업/재고/일정 **메뉴 숨김 + API 403** |
| **FULL** (전체 사용=현재 영업팀) | user/system 제외 전 업무권한 **50종** | 현재와 동일하게 전부 사용(무중단) |
| ADMIN(`role='ADMIN'`) | 와일드카드 | 관리(DB백업 등) 포함 전부 |

- **동작 원리**: 전자결재 라우터는 A 예외(자체 `require_auth`)라 권한 0이어도 동작. 다른 모듈은 `module_guard`라 권한 없으면 403. → "결재만" = 다른 모듈 권한 미부여.
- **default-deny**: 신규 계정은 RBAC 역할 자동 미부여 → 관리 화면에서 **반드시 배정**(영업팀=FULL / 나머지=APPROVAL_ONLY). 미배정자는 enforce에서 전 업무 차단(전자결재만 가능).
- **검증 완료**(실데이터 dev, enforce): APPROVAL_ONLY=결재 200·업무 403 / FULL=전부 200 / `rbac_enforced=true`. (`전자결재_RBAC_하이브리드_개발계획.md` §19)
- **확장 경로**: FULL → 추후 영업/생산/경영지원으로 분할(관리 화면 권한 체크만, 코드·마이그레이션 불필요).

### 13.1 전자결재 우선 도입 런북 (coarse 2역할, §11.3)
배포 후 전자결재만 먼저 여는 가장 안전한 순서:

1. **기존 영업팀 사용자 → FULL 역할 배정** (관리 → 권한 관리 → 사용자 역할). 현 capability 보존.
2. `RBAC_MODE=observe` 로 기동 → **영업팀 계정으로 하루 사용** → `[RBAC-MISS]` 로그 확인.
   - MISS 0 이어야 정상(FULL=50권한이 업무 전부 커버). MISS 나오면 그 권한을 FULL에 추가 후 재확인.
3. **전 직원 계정 생성 + 비영업 직원 → APPROVAL_ONLY 배정**. (미배정자는 enforce에서 전자결재만 가능 = default-deny라 안전하지만, 메뉴 노출 위해 APPROVAL_ONLY 배정 권장)
4. `RBAC_MODE=enforce` 전환(저트래픽 시간). → 영업팀=전부 그대로 / 비영업=전자결재만.
5. 이상 시 즉시 `RBAC_MODE=disabled`(env+재기동, 코드 롤백 불필요).
6. **확장(추후)**: 업무 프로세스 정착되면 FULL을 영업/생산/경영지원으로 분할(관리 화면 권한 체크만).

> 검증: 위 모델은 실데이터 dev에서 enforce로 **검증 완료**(APPROVAL_ONLY 업무 403·결재 200 / FULL 전부 200). 상세 `전자결재_RBAC_하이브리드_개발계획.md` §19.

### 13.2 배포 후 후속 작업 (운영 서버에서만 가능/안전한 것)
개발 단계에서 미리 못 박으면 위험한, **운영 환경 정보가 필요한** 작업들. 배포 후 처리.

> ⚠️ **이 서버는 인터넷 공개(public)** — 내부망 전용이 아님. 아래 항목 우선순위가 올라간다.

- [ ] **(우선) 배포 직후 `RBAC_MODE=observe` 로 무인증 창 닫기** — observe면 업무 라우터에 **로그인 강제(401)** 가 걸린다(권한 차단은 enforce). 공개 서버에서 업무 API 무인증 노출 시간을 최소화하려면 **배포 후 곧바로 observe**. (이후 §13.1 런북대로 enforce)
- [ ] **HTTPS(TLS) 적용/확인** — 공개망 평문 HTTP는 토큰·결재내용 도청 위험. 앞단 리버스프록시(nginx 등)+인증서, 또는 기존 프록시 구성 확인.
- [ ] **CORS 운영 도메인 제한 (권장)** — `.env.production`의 `BACKEND_CORS_ORIGINS=["*"]` → **직원이 실제 접속하는 주소**로 교체.
  - 이유: 올바른 값 = 운영 프론트 접속 origin(scheme+호스트+포트)이라 **서버에서 실주소 확인 후에만** 정확히 설정 가능. 추측 설정 시 scheme/포트 불일치로 **앱 전체 CORS 차단** 위험 → 개발 단계 미적용·후속 처리.
  - 방법: 운영 접속 주소 확인(예: `https://erp.도메인` 또는 `http://<서버IP>:5174`) → `BACKEND_CORS_ORIGINS=["<그 origin>"]`(여러 경로면 나열) → 재기동 → 로그인/화면 정상 확인 → 기동 CORS 경고 사라짐.
  - 공개 서버이므로 **선택 아닌 권장**(토큰 헤더 인증이라 치명적이진 않으나 defense-in-depth). HTTPS면 https origin으로.
- [ ] **(점검) 현재 운영(구버전) 노출 여부** — 통합 전 현 서버도 공개라면 업무 API 무인증 노출 가능. 앞단 프록시/방화벽/IP 제한 유무 확인.
- [ ] **후속 보안 정리(⑦⑧⑨, 유의사항 문서)**: 문서 채번 시퀀스화 / calendar·approvers·도장 과다노출 범위 제한(RBAC 연계) / 리포 위생(zip·.venv·backups 정리, git 도입).

## 14. 권장 배포 방법 (무중단 최대화)

> 전제: 스택 = FastAPI(uvicorn) + Vite 정적 프론트 + PostgreSQL, 앞단에 HTTPS 리버스프록시(nginx/IIS 등). 서비스 중단 최소화가 목표.

### 14.1 왜 무중단이 가능한가 (핵심 근거)
이번 마이그레이션은 **전부 가산적(additive)** — 신규 테이블 + nullable 컬럼 + `approval_projects→projects` rename 뿐이고, **구 운영 코드는 이 신규 객체를 전혀 참조하지 않음**(전자결재 모듈이 없던 버전). 따라서 **마이그레이션 후에도 구 코드가 그대로 동작**하고, **신·구 백엔드가 같은 DB를 동시에** 바라봐도 안전. → 블루-그린(대체 포트) 컷오버가 성립한다.

### 14.2 권장: 블루-그린 컷오버 (사용자 영향 ≈ 프록시 reload 1회)
1. **운영 DB 백업**(필수).
2. `alembic upgrade head` 적용 — 컬럼/테이블 추가라 빠르고 잠금 영향 미미. **구 백엔드(현 8001)는 계속 서비스**.
3. 프론트 빌드(`npm run build`) → **새 디렉터리**에 배치(기존은 그대로 둠).
4. **새 백엔드를 대체 포트(예: 8002)** 로 기동: `APP_ENV=production`, 우선 `RBAC_MODE=disabled`. 사용자는 아직 구 백엔드 사용 → 영향 0.
5. **8002 직접 스모크**(curl/브라우저로 8002): 로그인 → 기안→상신→승인→인쇄, **파일 다운로드/미리보기(R3)**, 영업 핵심 흐름.
6. 8002 를 **`RBAC_MODE=observe` 로 전환(8002만 재기동)** → 다시 스모크(인증 켠 상태에서 R3 등 깨짐 없는지). **여기까지 사용자는 계속 구버전 → 무영향.**
7. 검증 끝나면 **프록시 upstream 을 8001→8002 로 전환(reload)** + 웹루트를 새 프론트 디렉터리로. **이 순간이 유일한 컷오버**(프록시 reload, 거의 무중단). 사용자는 이제 **인증 켜진 신버전** → 무인증 구멍 닫힘.
8. 안정 확인 후 **역할 배정(FULL/APPROVAL_ONLY)** → 준비되면 8002 를 `enforce` 로(저트래픽 시 8002 재기동).
9. 구 백엔드(8001) 종료, 구 프론트 디렉터리 보관(롤백용).

> 롤백: 문제 시 프록시 upstream 을 다시 8001 로(즉시) — 구버전은 살아있으므로 무중단 복귀.

### 14.3 폴백: 인플레이스 재시작 (프록시 upstream 전환이 어려울 때)
1. DB 백업 → 2. `alembic upgrade head` → 3. 코드 교체 + 프론트 배포 → 4. 백엔드 **재시작(`disabled`)** → 5. 스모크 → 6. `RBAC_MODE=observe` 로 **재시작** → 스모크 → 7. 역할 배정 → `enforce`.
- 다운타임 = 재시작 수 초(저트래픽 창 권장). 롤백 = 코드/`RBAC_MODE=disabled` 되돌려 재시작.

### 14.4 공통 주의
- **`disabled` 로 오래 두지 말 것** — 그 사이 업무 API 무인증. 같은 작업창에서 `observe` 까지. (운영 부팅 시 `[SECURITY] RBAC_MODE=disabled` 경고 로그가 뜨도록 안전망 적용됨)
- **HTTPS**: 프록시에서 TLS 종단(공개 서버 필수). 신 백엔드도 동일 프록시 뒤에 둠.
- **PDF(`/pdf`)**: WeasyPrint GTK 미설치면 503(인쇄 HTML은 정상) — 필요 시 서버에 GTK 설치(`backend/docs/PDF_SETUP.md`).
- **첨부 storage**: `STORAGE_PATH` 경로/권한/백업 운영 기준 확인(신·구가 같은 경로 공유하면 컷오버 무관).
- `.env.production` 의 SECRET_KEY(강난수)·RBAC_MODE·CORS 확인. CORS 도메인 제한은 §13.2(배포 후 실주소).
