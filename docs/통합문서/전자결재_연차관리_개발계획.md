# 연차 관리 시스템 — 전자결재 연동 개발계획서

- 작성: 2026-06-22
- 근거: `연차 관리 정리.xlsx`(회사 정책) + 현재 코드(`leave_service.py`, LEAVE 결재 양식)
- 목적: 전자결재 휴가(연차) 결재에 **회계연도 기준 연차 발생·이월·정산 엔진**을 붙인다.

---

## 0. 현황 진단 (코드 실측)
- `leave_service.leave_balance(user, year)`: **entitlement = `users.annual_leave_days`(없으면 15) 고정**, used = 해당 연도 APPROVED LEAVE 문서의 차감대상(연차/반차) 합. remaining = entitlement − used.
- **누락**: 입사일 기반 발생, 회계연도 비례부여, 1년 미만 월별발생, 이월, 연차수당, 퇴사 정산 — **전부 없음**. 단일 정수로는 정책 표현 불가.
- 결재 연동: `approval_service`가 `compute_leave_days`만 호출(일수 계산). **하드 차감 없음**(잔여는 매번 계산식) → 원장 도입 시 이 구조를 활용/대체.

## 1. 회사 정책 요약 (엑셀)
**부여 = 회계연도(매년 1/1) 기준**
- **1년 이상 근로자**: 매년 1/1 자동 15일 + 전년 잔여 **이월**(단 **연차수당 지급분만큼 연초 차감**).
- **1년 미만 근로자**: 만근 가정하에 **해당 연도 발생분을 입사 시 일괄 부여**. 수당 없이 잔여 **전부 이월**.
- **자동화**: 매년 1/1 신규 연차 자동 생성 + 이월 반영.
- **원하는 기능**: ①퇴사 정산용 **연차수당 지급 개수 추적** ②1년 미만 입사자 중간 발생분도 **한 번에 부여**.

**정산**
- 매년 말 잔여 → 연차수당(1년 이상). 1년 미만은 수당 없이 이월.
- **퇴사 시: 입사년도(입사일) 기준 전체 발생연차 파악 → 사용·기지급수당 차감 정산.**

---

## 2. 부여 공식 (회계연도 기준) — 엑셀 예시로 검산
입사월 `HM`(1~12), 입사연도 `HY`, 대상 회계연도 `FY`.

| 구간 | 부여 시점 | 공식(일수) |
|---|---|---|
| **입사 첫 해** `FY=HY` | **입사일에 일괄** | `12 − HM` (다음달~12월 매월 1개 발생분을 입사 시 한꺼번에 부여) |
| **다음 해** `FY=HY+1` | **1/1 일괄** | (비례=**일수 기준**) `반차올림(15 × 전년재직일수/365)`(상한 15) **+** (입사 1년 이내 월차) `(HM−1)` |
| **3년차+** `FY≥HY+2` | 1/1 일괄 | `15 + 근속가산` = `15 + min(10, (n−1)//2)` (n=회계연도 근속연수 `fy−HY`). 3년 이상 2년마다 +1, 상한 25 |

> 정책 확정(2026-06-22): 첫 해 **입사일에 일괄**(잔여 개월수 일괄), 다음 해 **연초 일괄**(비례+월차), 3년차+ **연초 15**. 운영 중 부여는 회계연도 15 고정, **근속가산(법정)은 퇴사 정산에서만** 반영(아래).
> **비례분 = 일수 기준(2026-06-22 변경)**: 전년 재직일수(입사일~12/31 포함) ÷ 365 × 15, 반차(0.5) 올림, 상한 15. (이전 월수/12 방식 대체 — 더 정밀·법정 표준)

**검산(2025.09 입사, HM=9):**
- FY2025: `12−9 = 3` ✓ (10·11·12월)
- FY2026: 비례 `반차올림(15×122일/365=5.01)=5.5` + 월차 `(9−1)=8` = **13.5**
- FY2027: **15**
- 참고: 3월 입사 → 비례 `반차올림(15×306/365=12.57)=13.0` + 월차2 = **15.0** / 12월 입사 → `반차올림(15×31/365=1.27)=1.5` + 월차11 = **12.5**

**이월·잔여**
- `carried_in(FY) = remaining(FY−1) − allowance_paid(FY−1)` (1년 미만: paid=0 → 전부 이월)
- `remaining(FY) = carried_in(FY) + grant(FY) − used(FY)`

**퇴사 정산(법적 최소 보장)**
- 입사일 기준 발생 = 1년차 월별(최대 11) + 이후 매년 15(+근속). 회계연도 기준 부여와 비교해 **큰 쪽 − 사용 − 기지급수당** 으로 정산.

> ⚠️ **결정 필요**: ①비례부여 반올림 규칙(0.5/올림/내림) ②근속가산(3년차+1, 2년마다, 상한 25) 적용 여부 — 엑셀 미언급(현재 예시는 15 고정). §9 참조.

## 3. 데이터 모델 (신규/변경)

### 3.1 `users` 컬럼 추가 (마이그레이션, nullable → 기존 영향 0)
| 컬럼 | 타입 | 용도 |
|---|---|---|
| `hire_date` | DATE | **입사일 — 발생 계산 핵심(필수 입력)** |
| `resign_date` | DATE null | 퇴사일 — 정산 기준 |
| `employment_type` | VARCHAR null | (선택) 정규/계약 — 향후 정책 분기 |

> 기존 `users.annual_leave_days`(고정 15)는 **원장 도입 후 폐기/참고용**으로 강등.

### 3.2 `leave_ledger` (신규) — 연차 거래 원장 (단일 진실원천)
| 컬럼 | 설명 |
|---|---|
| id / user_id / fiscal_year(int) | 누구·어느 회계연도 |
| entry_type | `GRANT_ANNUAL`(연 발생) / `GRANT_MONTHLY`(월별발생 일괄) / `CARRYOVER_IN`(이월) / `USAGE`(사용) / `ALLOWANCE_PAID`(수당지급) / `ADJUST`(수동조정) |
| amount(float) | +발생/이월, −사용/수당지급/차감 |
| event_date | 발생/처리일 |
| source_type | `AUTO`/`APPROVAL`/`MANUAL` |
| source_doc_id(FK approval_documents null) | USAGE 시 결재문서 연결 |
| memo / created_by / created_at | 감사 |

→ **잔여 = Σ amount(해당 user, ≤FY 버킷 규칙)**. 모든 변동이 원장 1곳에 기록되어 감사·정산·이월이 일관됨.

### 3.3 (선택) `leave_year_summary` 캐시
표시·정산 속도용 연도별 집계(granted/carried_in/used/paid/remaining/carried_out). 원장에서 재생성 가능(없어도 됨, 성능 옵션).

## 4. 부여 엔진 + 자동화
`leave_accrual_service.py`(신규):
- `compute_grant(hire_date, fy)` — §2 공식.
- `ensure_ledger(user, upto_year)` — **idempotent**: 입사연도~현재연도까지 누락된 GRANT/CARRYOVER 원장 생성(중복 방지 키 = user+fy+entry_type). 이미 있으면 skip.
- `recalc_year(user, fy)` — 잔여/이월 재계산.

**자동화 트리거(둘 다 권장)**
1. **지연 생성(lazy)**: 로그인/연차조회 시 `ensure_ledger(user, 현재연도)` 호출 → **스케줄러 없이도** 1/1 자동 생성 효과(접속 시 보정). 내부망/단일서버에 적합.
2. **관리자 일괄 버튼**: "전 직원 N년도 연차 생성/이월" (수동 트리거, 미접속자 보정).
3. (선택) 진짜 cron이 가능하면 매년 1/1 배치 — 환경 갖춰지면 추가.

## 5. 전자결재(휴가) 연동
- **LEAVE 결재 APPROVED** → `USAGE` 원장 자동 생성(amount=−days, fiscal_year=시작일 연도, source_doc_id). 
- **반려/회수/관리자 정정-취소** → 해당 USAGE 원장 **역분개/삭제**(상태머신 훅).
- `leave_service.leave_balance` → **원장 기반으로 교체**(entitlement 고정값 제거). 휴가 작성화면의 "올해 N일 중 X 사용/잔여 Y"가 정확해짐.
- 잔여 부족 시 상신 경고(하드블록 여부는 §9 결정).

## 6. 정산 / 연차수당 (정책 확정)
- **연말 처리(관리자 수동)**: 연말 넘어갈 때 **관리 직원이** 잔여연차에 대해 수당 지급분을 `ALLOWANCE_PAID`로 입력 → 다음 해 `CARRYOVER_IN = 잔여 − 지급분`(지급분만큼 이월 차감). 1년 미만 → 수당 없이 전부 이월. (반자동: 시스템이 잔여를 보여주고 관리자가 지급일수 확정)
- **퇴사 정산(법정·노동부 규정)**: 퇴사 시 **입사일 기준 법정 연차**(1년차 월별 최대 11 + 이후 매년 15 + **근속가산** 3년↑ +1/2년마다·상한25)를 계산 → `법정 총발생 − 총사용 − 기지급수당` = **미정산 연차일수** 산출 → **마지막 퇴직금에 연차수당으로 정산**. 운영 부여(회계연도 15 고정)와의 차액이 여기서 true-up 됨. "기지급수당 개수"가 원장에 있어 바로 차감 가능.

## 7. 관리자 UI

### 7.0 접근 권한 — **경영지원팀이 연차 관리**
- 권한 레지스트리에 **`leave` 모듈 추가**(`leave:view`/`leave:manage`). 연차 관리 메뉴/화면은 `can('leave:manage')` 게이팅.
- `leave:manage` 부여: **경영지원팀(STAFF_MGMT) + ADMIN(와일드카드)**. (FULL 역할에도 포함되나 실 운영은 경영지원팀이 담당)
- 백엔드도 연차 관리 API에 `require_permission("leave:manage")` 부착(A 예외 라우터로).

### 7.1 연차 관리 화면 (경영지원팀, 신규 탭)
- **사용자별 연도별 표**(부여/이월/사용/**수당지급**/잔여) = 엑셀 "정리표"의 화면판. 원장 열람(감사).
- **강제 입력/오버라이드**: 자동계산이 기본이되, 칸별로 **수동 확정·수정 가능**(ADJUST 원장 + 사유 필수, "관리자 조정" 표식). → 자동값과 실제가 다를 때(특수 케이스·입사 전 이력 등) 강제 입력.
- **연말 수당 지급 입력창(연말 정산 패널)**: 연말 넘어갈 때 사용자별 잔여를 보여주고 → **관리자가 "수당 지급 일수"를 입력**(ALLOWANCE_PAID 기록) → 시스템이 **다음 해 이월 = 잔여 − 지급분** 자동 반영. (1년 미만자는 지급칸 비활성=전부 이월)
- **퇴사 정산 패널**: 입사일~퇴사일 선택 → 법정(입사일 기준+근속가산) 발생 − 사용 − 기지급수당 = **미정산 일수** 산출(퇴직금 반영용).
- **일괄 처리 버튼**: "N년도 연차 생성/이월"(미접속자 보정).

### 7.2 입사일/퇴사일 입력 (두 경로)
- **연차 관리 화면 상세 헤더**에서 직접 편집·저장(`PUT /leave/{id}/employment`, `leave:manage`) — **경영지원팀이 관리자 없이** 지정(v0.45.2). 변경 시 자동발생 재계산.
- 사용자 관리(관리자)에도 `입사일/퇴사일` 입력란(겸용).

### 7.3 본인 화면
- 내 연차 현황(발생·사용·잔여·이월 내역) 조회(읽기).

## 8. 도입(마이그레이션) — 초기 데이터가 관건
1. `users.hire_date/resign_date` 컬럼 추가(마이그레이션).
2. **기존 직원 입사일 입력**(필수) — 없으면 발생 계산 불가.
3. **도입 시점 초기 잔액 정합**: 두 방식 중 택1(§9 결정)
   - (A) 입사일부터 **전체 재계산**(과거 USAGE를 결재기록/엑셀에서 ADJUST로 주입) — 정확하나 과거 데이터 수집 필요.
   - (B) **도입 시점 현재 잔여만 ADJUST 초기 부여**로 세팅하고 이후부터 엔진 적용 — 간단, 과거 추적 포기.
4. 검증: 엑셀 예시 사번/실제 몇 명으로 부여·이월·정산 대조.

### 잔여/주의
- **법정 정산(`legal_entitlement`)은 노무/HR 검토 권장** — 근속가산·경계(입사일=조회일) 해석 차이 가능. 관리자 정산 패널에서 최종 확정(오버라이드 가능).
- 공휴일 반영(영업일 계산)은 기존과 동일하게 주말만 제외(Phase 추후).
- 본인 연차 상세 화면(`/leave/me`)은 API 제공 — 별도 본인 페이지는 차후(현재 휴가 작성화면 잔여 표시로 충분).
