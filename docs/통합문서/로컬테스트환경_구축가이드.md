# X-Manager 로컬 테스트 환경 구축 가이드

내 컴퓨터(Windows)에서 X-Manager를 띄워 직접 클릭하며 테스트하기 위한 안내서입니다.
전자결재 모듈을 개발·검증하기 전에, 먼저 **기존 시스템이 내 PC에서 돌아가는 상태**를 만드는 것이 목표입니다.

> 한 줄 요약: **Docker로 DB를 띄우고 → 운영 데이터를 복원하고 → 서버를 켠다.**

---

## 0. 큰 그림 (왜 이런 단계가 필요한가)

X-Manager는 3개가 한 세트로 돌아갑니다.

| 구성 | 역할 | 우리 PC에서 |
|------|------|-------------|
| **PostgreSQL (DB)** | 데이터 저장소 | Docker로 띄움 |
| **백엔드 (FastAPI)** | 업무 로직·API | Python 가상환경에서 실행 (포트 8001) |
| **프론트 (Vue)** | 화면 | Node로 실행 (포트 5174) |

지금 우리는 **개발 폴더(코드)만** 가져왔고 **DB는 비어 있는 상태**입니다.
그래서 DB를 새로 띄우고, 회사 운영 DB의 2026-04-07 백업(덤프)을 부어 넣어
실제 데이터로 테스트할 수 있게 만듭니다.

---

## 1. 한 번만 설치하면 되는 프로그램

아래 4개를 설치합니다. (이미 있으면 건너뛰기)

| 프로그램 | 용도 | 다운로드 |
|----------|------|----------|
| **Docker Desktop** | DB(PostgreSQL)를 손쉽게 띄움 | https://www.docker.com/products/docker-desktop/ |
| **Python 3.12+** | 백엔드 실행 | https://www.python.org/downloads/ (설치 시 "Add to PATH" 체크) |
| **Node.js 20 LTS** | 프론트 실행 | https://nodejs.org/ |
| (선택) **GTK3 Runtime** | PDF 출력 기능용 | docs/PDF_SETUP.md 참고 — 지금 당장은 없어도 앱은 켜짐 |

> Docker Desktop은 설치 후 **실행해서 켜 둔** 상태여야 합니다(작업표시줄 고래 아이콘).

---

## 2. 한 번만 하는 백엔드 준비

`서버 코드 폴더(X-MANAGER_R0.1)` 안에서 진행합니다. (탐색기 주소창에 `cmd` 입력 → 그 폴더에서 명령창 열기)

```bat
cd backend

REM 가상환경 생성 (이름은 .venv — start-dev.bat 이 이 이름을 사용함)
python -m venv .venv

REM 가상환경 켜기
call .venv\Scripts\activate.bat

REM 패키지 설치
pip install -r requirements.txt

REM 로그인 암호화 호환 버전 (서버 설치 가이드 기준)
pip install bcrypt==4.0.1
```

> WeasyPrint(PDF) 관련 에러가 나도 무시하고 진행하세요. PDF 출력만 영향받고
> 나머지 기능 테스트에는 지장이 없습니다. PDF까지 테스트하려면 docs/PDF_SETUP.md 의 GTK3 설치를 합니다.

---

## 3. 한 번만 하는 프론트엔드 준비

새 명령창에서:

```bat
cd frontend
npm install
```

## 4. DB 띄우고 데이터 복원 (자동 스크립트)

제가 만들어 둔 **`setup-local-db.bat`** 를 더블클릭하면 아래가 자동으로 됩니다.

1. Docker로 PostgreSQL 16 컨테이너 실행 (`xmanager-postgres`)
2. 20초 대기 (DB 초기화)
3. `xmanager_2026-04-07_production.dump` (운영 백업) 복원

복원 중 권한/소유자 관련 **경고 메시지는 정상**입니다(무시 가능).

> 직접 명령으로 하고 싶다면:
> ```bat
> docker compose -f docker\docker-compose.yml up -d
> docker exec -i xmanager-postgres pg_restore -U xmanager -d xmanager_dev --no-owner --clean --if-exists < xmanager_2026-04-07_production.dump
> ```

### DB 접속 정보 (정리된 값)

| 항목 | 값 |
|------|-----|
| 호스트/포트 | localhost : 5432 |
| DB 이름 | xmanager_dev |
| 사용자 | xmanager |
| 비밀번호 | xmanager1014 |

> ⚠️ 원래 `backend/.env.development` 의 DB 접속정보가 docker 설정과 **서로 달랐습니다**
> (DB이름·비밀번호 불일치). 이번에 docker 기준으로 **맞춰서 수정**해 두었습니다.

---

## 5. 서버 켜고 접속하기

`서버 코드 폴더` 의 **`start-dev.bat`** 더블클릭. 검은 창 2개(백엔드/프론트)가 뜹니다.

- 백엔드: http://localhost:8001  (API 문서: http://localhost:8001/docs)
- 프론트: **http://localhost:5174**  ← 브라우저로 이 주소 접속

로그인은 **평소 쓰던 X-Manager 계정**으로 합니다. (운영 덤프를 복원했으므로
회사에서 쓰는 아이디/비밀번호가 그대로 들어 있습니다.)

---

## 6. 평소 사용 (2회차부터)

설치는 끝났으니 이후에는 두 가지만 하면 됩니다.

1. Docker Desktop 켜져 있는지 확인 (컨테이너는 자동 재시작됨)
2. `start-dev.bat` 더블클릭 → http://localhost:5174

끄기: 검은 창 닫기 + (원하면) Docker Desktop에서 `xmanager-postgres` 정지.

## 7. 문제 해결 (자주 나는 것들)

| 증상 | 원인 / 해결 |
|------|-------------|
| `Docker 실행 실패` | Docker Desktop이 안 켜짐 → 켜고 30초 후 다시 실행 |
| `password authentication failed` | `.env.development` 와 docker 값 불일치 → 4장 접속정보로 맞춤 (이미 수정함) |
| `database "xmanager_dev" does not exist` | 컨테이너가 처음 뜰 때 생성됨. `docker compose ... up -d` 다시 실행 후 20초 대기 |
| 포트 5432 충돌 | PC에 PostgreSQL이 이미 설치돼 5432 사용 중 → 그 서비스 정지하거나 docker-compose 포트를 5433으로 변경 |
| 포트 8001/5174 충돌 | 다른 프로그램이 사용 중 → 해당 프로그램 종료 |
| 로그인 안 됨 | 운영 덤프 복원이 됐는지 확인. 안 됐으면 빈 DB라 계정이 없음 → 4장 재실행 |
| `alembic upgrade` 에러 | 운영 덤프(4/7)와 코드(v0.32) 사이 버전 차이일 수 있음 → 8장 참고 |
| WeasyPrint / PDF 에러 | GTK3 미설치. 앱은 정상, PDF 출력만 안 됨 → docs/PDF_SETUP.md |

## 8. (개발 단계에서) 스키마 최신화 — 전자결재 개발 시작 전

운영 덤프는 2026-04-07 시점이라 코드(v0.32.0)보다 스키마가 조금 과거일 수 있습니다.
**전자결재 테이블을 추가하는 개발을 시작하기 직전에** 한 번 최신화합니다.

```bat
cd backend
call .venv\Scripts\activate.bat
set APP_ENV=development
python -m alembic upgrade head
```

- 정상: `Running upgrade ...` 메시지가 여러 줄 출력 → 최신 스키마 반영 완료
- 만약 `Can't locate revision` 등 에러가 나면, 운영 브랜치와 마이그레이션 이력이 어긋난
  경우입니다. 그땐 **빈 DB로 시작**(덤프 복원 없이 `alembic upgrade head`만)하거나,
  저에게 덤프의 `alembic_version` 값을 알려주시면 맞춰 드리겠습니다.

> 전자결재 모듈 개발이 시작되면, 새 마이그레이션(v0.33.0)이 추가되고
> 위 `upgrade head` 한 번으로 결재 테이블이 생성됩니다.
