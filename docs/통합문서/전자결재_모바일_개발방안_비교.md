# 전자결재 모바일(안드로이드·iOS) 개발 방안 비교

- 작성일: 2026-06-20
- 대상: X-Manager 전자결재 모듈을 직원 휴대폰(안드로이드·iOS)에서 사용
- 현재 스택: Vue 3 + Vite SPA(프론트) / FastAPI(백엔드) / PostgreSQL
- 규모: 직원 10~30명 (사내용, 방산업체)

---

## 0. 핵심 결론 (요약)

> **기존 Vue 코드를 버리지 말고 재사용한다.**
> 1단계로 **반응형 웹 + PWA**(즉시·저비용), 필요해지면 2단계로 **Capacitor**로 같은 코드를 네이티브 앱(안드로이드/iOS)으로 감싼다.
> React Native/Flutter 전면 재작성은 사내 30명 규모엔 과하다.

---

## 1. 현황과 제약

- 이미 **Vue 3 SPA**가 있고 반응형 일부(상단/모바일 메뉴)도 들어가 있음.
- 백엔드는 JWT 인증 + REST API. 프론트 `client.ts`가 **접속 도메인 기준으로 API URL 자동 결정**(운영 도메인이면 `/api/v1`).
- 현재는 **LAN(192.168.x)** 에서만 구동 → 같은 WiFi의 폰에서는 지금도 접속 가능하나, **사무실 밖(셀룰러)에서는 불가**.
- 우리가 만든 기능 중 모바일 네이티브와 궁합이 좋은 것: **파일 첨부, 영수증/서명 촬영, 결재 대기 푸시 알림**.

---

## 2. 방식 비교

| 항목 | A. 반응형 웹 + PWA | B. Capacitor (권장 네이티브) | C. React Native / Flutter |
|------|------|------|------|
| 기존 Vue 재사용 | ✅ 그대로 | ✅ 95% 그대로 감쌈 | ❌ UI 전면 재작성 |
| 코드베이스 수 | 1개 | 1개(웹=앱 공유) | 2~3개(웹 별도+앱) |
| 안드로이드/iOS | 브라우저로 둘 다 | 네이티브 앱 둘 다 | 네이티브 앱 둘 다 |
| 앱스토어 배포 | ❌ (URL 공유/홈화면 추가) | ✅ Play/App Store/사내배포 | ✅ |
| 푸시 알림 | △ (iOS는 16.4+ 설치형만) | ✅ FCM/APNs 네이티브 | ✅ |
| 카메라/생체인증/파일 | △ 제한적 | ✅ 네이티브 플러그인 | ✅ |
| 오프라인 | △ 캐시 수준 | △~✅ | ✅ |
| 개발 난이도/비용 | 낮음 | 중간 | 높음 |
| 예상 착수 기간 | 0.5~1주 | +1~2주(웹 완료 후) | 4~8주+ |
| 유지보수 | 가장 쉬움 | 쉬움(웹과 공유) | 무거움 |

### A. 반응형 웹 + PWA
- 기존 화면을 모바일 폭에 맞게 다듬고, `manifest.json` + 서비스워커로 **홈 화면 설치·앱처럼 실행**.
- 👍 가장 빠르고 싸다, 배포·심사 없음, 즉시 양 OS.
- 👎 iOS 푸시 제한, 카메라/생체인증 등 네이티브 기능 약함, 앱스토어에 없음.

### B. Capacitor (권장)
- Ionic **Capacitor**가 빌드된 Vue(웹) 결과물을 네이티브 컨테이너(WebView)로 감싸 **안드로이드/iOS 앱**으로 만든다.
- 같은 Vue 코드 → 웹·안드로이드·iOS 동시 운용. 플러그인으로 **푸시(FCM/APNs)·카메라·생체인증·파일·공유** 사용.
- 👍 기존 자산 최대 재사용 + 네이티브 기능 + 앱스토어. 사내 규모에 최적의 균형.
- 👎 빌드 환경 필요(iOS는 **macOS + Xcode** 필수), 스토어/배포 계정·서명 작업.

### C. React Native / Flutter
- 진짜 네이티브 UI/성능. 그러나 **프론트를 다른 언어/프레임워크로 재작성**.
- 👍 최고 수준 UX/성능, 복잡한 모바일 전용 UX.
- 👎 비용·기간·유지보수 부담 큼. 이미 있는 Vue를 버림. 30명 사내 결재앱엔 과투자.

## 3. 추천 경로 (단계별)

### 1단계 — 반응형 + PWA  (즉시, 0.5~1주)
1. 전 화면 모바일 반응형 점검(목록/작성/상세/캘린더/관리, 표→카드형, 터치 타깃)
2. PWA: `manifest.json`(아이콘/이름/테마색) + 서비스워커(앱 셸 캐시) + "홈 화면에 추가" 안내
3. 같은 WiFi 폰에서 즉시 테스트 → 사내 우선 배포
- 산출: 직원이 폰 브라우저/홈화면 아이콘으로 결재 사용

### 2단계 — 운영 공개 인프라  (모바일 외부 사용 전 필수)
1. 백엔드 **HTTPS 도메인** 배포(기존 AWS + Caddy/Nginx) — 셀룰러에서도 접속
2. **보안 3건 선처리**(`전자결재시스템_보안보완_체크리스트.md`: SECRET_KEY·traceback·CORS) — 외부 노출 시 필수
3. CORS/도메인 화이트리스트, 토큰 만료/리프레시 점검

### 3단계 — Capacitor 네이티브 앱  (앱스토어·푸시·카메라 필요 시, +1~2주)
1. Capacitor 추가(`@capacitor/core` + android/ios 플랫폼), 기존 Vue 빌드 산출물 래핑
2. 플러그인: Push(FCM/APNs), Camera(영수증·서명 촬영), Biometric(생체 로그인), Filesystem/Share
3. 백엔드 **푸시 발송**(디바이스 토큰 저장 + FCM/APNs 전송) — "결재 대기/반려/완료" 알림
4. 빌드·서명·배포: 안드로이드(Play 또는 내부 APK/MDM), iOS(TestFlight/Apple Business Manager 사내배포)

## 4. 공통 선행 조건 (방식 무관)

| 항목 | 내용 |
|------|------|
| 외부 접속 | LAN → **HTTPS 도메인** 필요(셀룰러). 현재 `client.ts`가 도메인 기반 `/api/v1` 지원 |
| 보안 | 외부 노출 시 SECRET_KEY 등 보안 체크리스트 **필수** |
| 인증 | JWT 그대로 사용(토큰 저장/리프레시). 생체인증은 Capacitor 단계 |
| 알림 | 초기 인앱/이메일 → Capacitor 단계에서 네이티브 푸시 |
| 배포 계정 | iOS: **Apple Developer $99/년**(+macOS/Xcode). 안드로이드: Play $25 1회 또는 내부 배포/MDM |

## 5. 의사결정 가이드

- **"앱스토어 없이, 빨리, 무료로 폰에서 쓰면 된다"** → **1단계(반응형 PWA)만으로 충분.**
- **"홈화면 아이콘 + 푸시 알림 + 영수증/서명 카메라 + 생체로그인까지"** → **1단계 후 3단계(Capacitor).**
- iOS 앱 빌드/배포에는 **macOS 장비와 Apple Developer 계정**이 반드시 필요(이 부분이 실무 병목).

## 6. 권장 시작점

**1단계(반응형 + PWA)부터** 시작을 권장합니다 — 위험·비용이 가장 낮고, 같은 WiFi에서 즉시 폰으로 검증하며 직원 피드백을 받을 수 있습니다. 푸시·카메라·앱스토어가 실제로 필요해지는 시점에 3단계(Capacitor)를 같은 코드로 얹으면 됩니다.

> 다음 행동 후보:
> 1) 반응형 점검 + PWA 매니페스트/서비스워커 추가 (즉시 폰 사용 가능)
> 2) 운영 HTTPS 배포 + 보안 3건
> 3) Capacitor 스캐폴딩 + 푸시 설계

## 7. 모듈형(부분별) 앱 구조 — 전자결재 · 구매관리 …

핵심 원칙: **여러 개의 앱이 아니라, 하나의 앱 안에서 기능을 모듈로 나눈다.**
(모듈마다 별도 앱 = 설치/로그인 N번, 푸시·인증 중복 → 비권장. 한 앱·한 로그인·모듈 분리가 정답.)

### 7.1 전체 구조

```
[모바일 앱 (1개 설치, 1회 로그인)]
   홈(런처): 권한 있는 모듈 타일만 표시 (배지: 결재대기 N 등)
   ├─ 전자결재  모듈   (완성)
   ├─ 구매관리  모듈   (발주/입고)
   ├─ 영업관리  모듈
   ├─ 생산관리  모듈
   └─ 재고/거래처 …   (필요 모듈만 점진 추가)
        ▲ 각 모듈 = 독립 폴더(화면+API+스토어+라우트), 지연 로딩
        ▼ 공유 코어
   [코어] 인증 · API 클라이언트 · 레이아웃 · 알림 · 공통 컴포넌트
```

### 7.2 모듈 = 독립 단위 (부분별 개발의 핵심)
각 모듈은 자기 것만 담은 한 폴더로 구성 → **다른 모듈 안 건드리고 개발·테스트·배포**.

```
src/modules/
  approval/      # 전자결재 (이미 있는 views/api/stores를 이 단위로 정리)
    routes.ts    # /m/approval/*
    api.ts
    store.ts
    views/
    module.ts    # 모듈 메타: { key, title, icon, roles, badge() }
  purchase/      # 구매관리
  sales/  production/ ...
src/core/        # 공유: auth, client, layout, push, ui
src/modules/registry.ts   # 활성 모듈 목록(런처/메뉴/라우트가 여기서 자동 구성)
```

- **모듈 레지스트리**: `registry.ts`에 모듈 메타를 등록하면 **홈 런처·네비·라우트가 자동 생성**. 새 모듈 추가 = 폴더 만들고 레지스트리에 한 줄 등록.
- **지연 로딩(lazy import)**: 라우트 단위 코드 분할 → 앱은 사용하는 모듈만 로드(가볍고, 모듈 추가가 다른 모듈에 영향 없음).
- **권한/노출 제어**: 모듈 메타의 `roles`/`department` 로 **사용자별로 보이는 모듈만** 런처에 표시. 미완성 모듈은 `enabled:false` 플래그로 숨겨 **점진 출시**.
- **배지/알림**: 모듈별 `badge()`(예: 결재대기 N)와 푸시 채널 분리 가능.

> 웹과 앱은 같은 Vue 코드이므로, 이 모듈 구조는 **웹·PWA·Capacitor 앱에 동일 적용**됩니다. 모바일은 홈 런처+하단 탭 같은 모바일 셸만 추가.

### 7.3 기존 코드와의 관계
지금 웹 프론트는 이미 도메인별(views/api/stores)로 나뉘어 있어, 이를 **모듈 폴더 규약으로 정리 + 레지스트리 도입**하면 큰 재작성 없이 모듈형이 됩니다. 백엔드는 이미 도메인별 라우터(`api/v1/*`)라 그대로 모듈과 1:1.

### 7.4 부분별 출시 순서(제안)
1. **전자결재** (이미 완성) — 모바일 첫 모듈로 출시
2. **구매관리**(발주 승인/조회) — 결재와 연결성 높음
3. 영업/생산/재고 현황 조회 — 모바일에서 가치 큰 "조회" 위주부터
4. 입력이 무거운 기능은 웹 우선, 모바일은 조회·승인 중심으로 범위 조정

### 7.5 모바일 모듈 범위 팁
폰에서는 **승인·조회·알림·촬영(영수증/서명)** 이 핵심. 대량 입력/표 편집은 웹에 두고, 모바일 모듈은 "보고 · 결재하고 · 찍어 올리는" 흐름 위주로 설계하면 만족도가 높습니다.

---

## 8. 권장 시작점 (갱신)

1. **반응형 + PWA**로 전자결재부터 폰 사용 가능하게 (1단계)
2. 동시에 **모듈 폴더 규약 + 레지스트리** 도입(전자결재를 첫 모듈로) → 이후 구매관리 등은 모듈 추가만으로 확장
3. 외부 사용 필요 시 HTTPS 배포 + 보안 3건 → 그다음 Capacitor + 푸시

이 구조면 "전자결재 먼저, 구매관리 다음" 처럼 **부분별로 안전하게 하나씩** 얹을 수 있습니다.
