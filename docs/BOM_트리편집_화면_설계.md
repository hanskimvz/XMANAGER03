# BOM 트리 구축·편집 화면 — 설계 명세 (v0.2 / 2026-09)

> 담당자 아이디어(좌측 **부품 List** → 우측 **BOM 트리** 드래그 조립)에 실사용·예외·기존 코드
> 정합성을 더한 문서. **v0.2 반영 결정 4건**(아래 "결정 사항") 포함. 대상: 개발/기획 리뷰용.

## 결정 사항 (v0.2에서 확정)

1. **확인창 없음.** "하위냐 같은 레벨이냐"는 **드롭 위치 + 실시간 미리보기**로 판별한다(§5).
2. **팔레트 = 찾기 또는 만들기(find-or-create).** 코드 선등록 불필요 — 검색으로 재사용하거나, 없으면 그 자리에서 이름만으로 생성(미분류). (§3)
3. **순서는 입력한 순서대로 쌓기(append).** 정렬 삽입 기능은 후순위. (§6)
4. **조회 화면과 편집 화면 분리.** 현재 BOM 화면 = 조회 전용, 편집은 **전용 전체화면(별도 라우트 권장)**. (§2, §9)
5. **같은 부모에 같은 부품 중복 시 수량 자동 합산**(토스트 안내, 차단 확인 없음). (§5.4)

## 1. 목표 & 컨셉

**한 줄 요약** — "등록된(또는 방금 만든) 부품을 **끌어다 놓아** 제품의 계층 구조(BOM)를 눈으로 조립한다."

- 담당자 흐름
  1. 부품을 먼저 확보 (엑셀 일괄 업로드 · 편집 화면에서 즉석 생성).
  2. 좌측 **부품 List**에서 부품을 끌어 우측 **BOM 트리**의 원하는 자리에 놓는다.
  3. **어디에 놓느냐**(행 위/행 사이)로 하위·형제가 정해진다 — 별도 질문 없음.
- 지금 구현(🧩 트리 편집기)과의 관계
  - 있는 것: 트리 안 **노드 이동(드래그 reparent)**, 인라인 수량, 미분류 즉석 추가, 첨부/분류/병합, 완결성 체크.
  - **이 설계가 더하는 것**: 좌측 **부품 팔레트(List)** + *팔레트 → 트리* 드래그(기존 부품을 구조에 배치),
    그리고 이 모든 편집을 담는 **전용 편집 화면**.
  - 두 방식 공존: **구조 먼저(미분류 즉석 생성)** ↔ **부품 먼저(팔레트에서 끌어다 배치)**.

## 2. 화면 구성 — 조회 / 편집 분리

### 2.1 조회 화면 (현행 BOM 탭, 유지)
- 현재의 상위 부품 선택 + BOM 구성/트리 뷰 + 원가 + 완결성 체크. **읽기·확인에 최적화**.
- 여기에 **[✎ BOM 편집]** 버튼을 둔다 → 편집 화면으로 진입. (실수 편집 방지 겸 모드 분리)

### 2.2 편집 화면 (신규, 전체화면)
- 진입: 조회 화면의 [✎ 편집] 또는 시작 위저드 완료 직후. 라우트 예: `/bom/:partId/edit`.
- 전체 폭을 써서 좌(팔레트) / 우(트리 캔버스) 2분할. 상단 편집 툴바.
- 나가기: **[완료/닫기]** → 조회 화면 복귀. (편집은 즉시 저장되므로 "저장" 대신 "완료".)

```
┌ 편집 화면 (전체화면) ─────────────────────────────────────────────────────────┐
│ ◀ 완료   [제품] HXB13-PSD 커넥터 키트     🔍  ⟲되돌리기 ⟳다시   원가재계산  완결성 ✓│
├──────────────────────┬────────────────────────────────────────────────────┤
│  부품 List (팔레트)   │   BOM 트리 구조                                        │
│ ┌──────────────────┐ │  ● HXB13-PSD 커넥터 키트            (최상위)          │
│ │🔎 검색…          │ │  └ ▸ 본체 어셈블리            ×1  📎2                 │
│ │필터 ☑미배치만    │ │     ├ 하우징                  ×1  [미분류]            │
│ ├──────────────────┤ │     └ 핀                      ×24                    │
│ │⋮⋮ 하우징  배치×1  │ │  └ ▸ 캡                       ×2                     │
│ │⋮⋮ 핀      배치×1  │─┼──드래그──▶ (아래 §5의 두 구역으로 하위/형제 결정)      │
│ │⋮⋮ 오링    배치×0  │ │                                                     │
│ │ [+ 새 부품]      │ │                                                     │
│ └──────────────────┘ │                                                     │
└──────────────────────┴────────────────────────────────────────────────────┘
```

## 3. 좌측 — 부품 List (팔레트) = 찾기 또는 만들기

**팔레트는 "부품을 미리 등록해 두는 곳"이 아니라, 검색창 하나로 재사용·생성을 겸하는 곳이다.**
검색어를 치면 (a) 있으면 결과에서 끌어 쓰고(재사용), (b) 없으면 **"'○○' 새로 만들어 추가"** 로 미분류 즉석 생성.
→ **코드 선등록 강제 없음.** "구조 먼저, 코드 나중" 원칙 유지.

| 요소 | 설명 |
|---|---|
| **검색창(find-or-create)** | 품번/품명 즉시 검색. 결과 없으면 하단에 **"‘○○’ 새로 만들어 추가"**(미분류 생성) |
| **필터** | 대분류(제품라인)·레벨코드·단위 등. `PartFilterPanel` 재사용 |
| **☑ 미배치만** | 현재 트리에 아직 없는 부품만 표시 → "무엇이 남았나" 파악 |
| **부품 카드** | `⋮⋮ 핸들 · 품번 · 품명 · [미분류] · 배치×N`. 미분류(이름만) 부품도 표시됨 |
| **배치×N 배지** | 이 부품이 트리에 몇 번 쓰였는지. 0이면 흐리게 |
| **빈 상태** | "부품을 검색하거나 이름을 입력해 새로 만들 수 있습니다 · 엑셀 일괄 업로드" |

### 3.1 부품을 어디서 만드나 — 상황별 권장
신규 부품 생성 경로는 **두 곳**이며, 상황에 따라 더 빠른 쪽을 쓴다(둘 다 미분류 최소등록).

| 상황 | 권장 |
|---|---|
| 처음 만드는 **신규 부품** | 우측 트리의 **하위 추가**에서 이름 입력 → 바로 생성·배치(팔레트보다 단계 적음) |
| **기존/표준/공용 부품 재사용** | 좌측 팔레트에서 검색 → 드래그 |
| 이미 **엑셀로 부품을 다 올림** | 팔레트에서 끌어다 **구조만 조립** |

> 드래그 대안(터치·반복 작업용): 카드 **더블클릭** = "현재 선택된 트리 노드의 하위로 추가".

## 4. 우측 — BOM 트리 캔버스

기존 `BomTreeEditor`/`BomNode` 확장. 노드 1줄 구성은 현행 유지:

```
⋮⋮  ▸  품번  품명  [미분류]  📎N   ×수량 단위        ⋯메뉴
```
수량 인라인 수정, 접기/펼치기, ⋯메뉴(첨부·분류·병합·삭제)는 현행 그대로.

## 5. 드래그 & 드롭 — "하위냐 형제냐"를 위치로 판별 (질문 없음) ★핵심

확인창을 없애는 대신, **드롭 지점을 두 구역으로 나누고, 손을 떼기 전에 결과를 미리보기**로 보여준다.
(VS Code 탐색기·Notion·Figma 레이어와 같은 방식 — 사용자가 직관적으로 익힘.)

### 5.1 두 개의 드롭 구역

| 올려놓는 위치 | 결과 | 화면 미리보기 |
|---|---|---|
| **행 몸통(가운데)** | 그 부품의 **하위(자식)** 로 추가 | 대상 행 전체가 파랗게 강조 + "⤷ ○○의 하위로" |
| **행과 행 사이(경계선)** | **같은 레벨(형제)** 로 추가 | 그 자리에 **가로 삽입선**, 들여쓰기로 레벨 표시 |
| **트리 빈 공간** | **최상위 바로 아래** 로 추가 | 캔버스 하단 강조 |

```
[하위로] 행 몸통에 올릴 때              [형제로] 행 사이 경계선에 올릴 때
  ▸ 본체 어셈블리   ◀ 행 전체 강조         ▸ 본체 어셈블리
     · · ⤷ 하위로 추가 · ·                ───────────────  ◀ 삽입선(같은 레벨)
                                          ▸ 캡
```

- **놓기 전에 이미 결과가 보이므로** 오배치가 거의 없다 → 확인창 불필요.
- 판정 기준(구현): 마우스 Y좌표가 행 높이의 **가운데 약 60%** 면 "하위(into)", **위/아래 20% 경계** 면 "형제(between)".
- **수량**은 기본 1로 추가하고 트리에서 바로 인라인 수정(입력 팝업 없음).
- **안전장치(질문 대신)**: 드롭 직후 상단에 **실행취소 스낵바** 3~5초 —
  "하우징을 본체 어셈블리 하위로 추가 · [실행취소]".

### 5.2 소스/대상 매트릭스

| 소스 → 대상 | 결과 |
|---|---|
| 팔레트 부품 → 행 몸통 | 그 부품의 **하위로 추가** |
| 팔레트 부품 → 행 사이 | 그 위치의 **형제로 추가**(같은 부모) |
| 팔레트 부품 → 빈 공간 | 최상위 하위로 추가 |
| 트리 노드 → 행 몸통/사이 | **이동**(reparent, 현행 `H.reparent`) |
| 팔레트 다중선택 → 대상 | 선택 부품 **일괄 추가** |

### 5.3 드래그 페이로드 (구현)
기존 `drag`에 `kind`를 추가해 소스를 구분:
```ts
type BomDrag =
  | { kind: 'tree-move'; bomId: number; partId: number; name: string }  // 트리 내 이동(현행)
  | { kind: 'palette-add'; partId: number; name: string }              // 팔레트 → 트리(신규)
```
드롭 핸들러는 `(kind, 대상 노드, into|between)` 조합으로 분기.

### 5.4 유효성 (드롭 거부/경고)

| 상황 | 처리 |
|---|---|
| **순환 참조**(상위를 자기 하위로) | 드롭 거부 + 빨강 미리보기 "순환 구조 불가" (`check_circular_reference` 기존) |
| **자기 자신 위** | 무시 |
| **같은 부모에 같은 부품 중복** | **수량 자동 합산**(예: 2→3) + 토스트 "수량을 합쳤습니다". 차단 확인 없음(§결정5) |
| 다른 가지의 같은 부품 | 허용(공용 부품 정상) |

## 6. 수량 · 순서 · 레벨 · 코드

- **수량 = 상위 1개당 소요량**. 기본 1, 인라인 수정.
- **순서 = 입력한 순서대로 append**(§결정3). 순서 규칙이 있으면 담당자가 그 순서로 넣는다.
  - 나중에 순서를 바꾸고 싶으면 §5의 "행 사이" 드롭으로 재배치 가능(후순위 기능).
- **트리 레벨(깊이)** = 어디에 드롭했는가로 자동 결정. 숫자 지정 불필요.
- **부품 품번/레벨코드** = 부품 속성. 배치해도 안 바뀜. 미분류면 나중에 ⋯→분류/채번.

---

## 7. 좌 ↔ 우 동기화 · Undo

- 배치/삭제 시 팔레트의 **배치×N 배지**·**미배치 필터** 즉시 갱신.
- **Undo/Redo**(툴바 ⟲⟳): 1차는 "최근 1건 실행취소" 스낵바 → 이후 다단계 스택.

---

## 8. 예외 · 엣지 케이스

- **팔레트에 부품 없음** → [+ 새 부품] 즉석 생성(미분류) 후 배치.
- **대량 배치 성능** → 팔레트 가상 스크롤, 드롭은 낙관적 업데이트 후 서버 반영.
- **동시 편집** → (별도 과제) 저장 충돌·잠금은 BOM 개편 "동시편집 잠금"과 연계.
- **터치/태블릿** → 더블클릭/선택-후-추가 클릭 경로 제공.
- **완결성** → 편집 후 완결성 체크(미분류/도면없음/원가/수량)로 사후 점검.

---

## 9. 진입/이탈 & 기존 구현과의 관계

- **진입**: 조회 화면 [✎ BOM 편집] · 신규 제품 시작 위저드 완료 직후 → 편집 화면.
- **이탈**: [완료/닫기] → 조회 화면 복귀(편집은 즉시 저장됨).
- 재사용 자산: `BomTreeEditor`(provide/inject `bomDrag`·`bomHandlers`), `BomNode`(드롭존),
  `PartFilterPanel`, `partApi.getAll/createMinimal`, `bomApi.create/move/createBulk`, `check_circular_reference`.
- 신규: 편집 화면 라우트/레이아웃, 팔레트(`BomPartPalette.vue`), 두 구역 드롭 로직(into/between),
  `bomDrag`에 `kind`, 배치수 집계, Undo 스낵바.
- **좌측 패널 토글 문제 해소**: 편집이 별도 화면이라 기존 조회 화면은 손대지 않아도 됨.

## 10. 구현 Phase

| Phase | 범위 | 산출 |
|---|---|---|
| **P1 편집 화면 + 팔레트 + 기본 드롭** | 전체화면 라우트, 좌측 부품 List(검색/필터), 팔레트→(하위/형제/빈공간) 드롭 + 실시간 미리보기, 실행취소 스낵바 | 눈으로 조립 가능 |
| **P2 정합성·동기화** | 순환/중복 검증 미리보기, 배치×N 배지·미배치 필터 | 실무 사용성 |
| **P3 편의** | 더블클릭/키보드 배치, 다중선택 일괄 드롭, 순서 재배치(행 사이) | 속도·접근성 |
| **P4 고급** | 다단계 Undo/Redo, 가상 스크롤, 동시편집 잠금 연계 | 대규모·협업 |
