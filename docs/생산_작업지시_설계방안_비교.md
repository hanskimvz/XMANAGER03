# X-Manager 생산 작업지시 설계 방안 비교

**작성일**: 2026-04-10
**목적**: 영업 → 생산 전환 단계에서 작업지시서 구조를 어떻게 설계할지 의사결정을 위한 비교 분석

---

## 1. 배경

### 1.1 현재 상황

X-Manager의 영업 프로세스(영업활동 → 견적서 → PI → 생산요청)는 구현 완료되어 운영 준비 중입니다.
다음 단계인 **생산요청 → 작업지시** 구간의 설계 방향을 결정해야 합니다.

### 1.2 생산 현장의 실제 작업 유형

하나의 제품을 만들기 위해 여러 종류의 작업이 발생합니다:

| 유형 | 설명 | 예시 |
|------|------|------|
| **고객 주문 생산** | PI 기반, 생산요청서에 연결 | 고객 주문 100ea 제조 |
| **재고 보충 생산** | 주문 없이 선제적 생산 | 공용 인서트 부품 500ea 선행 제조 |
| **외주 가공/구매** | 외부 업체에 발주 | 본체 정밀가공 외주 |

### 1.3 제품 1개의 생산 공정 예시

```
완제품: HXB13 4채널 관통 커넥터 100ea

공정 1: 인서트 부품 제조 (자체 생산, 인서트팀)
공정 2: 커넥터 본체 가공 (외주, OO정밀)
공정 3: 조립 + 검사 (자체, 조립팀 + 품질팀)
공정 4: 케이블 작업 (자체, 조립팀)
공정 5: 최종 검사 + 포장 (자체, 품질팀)
```

### 1.4 핵심 질문

> **하나의 제품 생산에 여러 공정이 필요할 때, 작업지시서를 어떻게 구성할 것인가?**

---

## 2. 두 가지 설계 옵션

### 옵션 A: 작업지시서 1개 + 공정(Task)으로 관리

```
생산요청서 (PR-001)
  └── 작업지시서 1개 (WO-001, HXB13 100ea)
        ├── 공정 1: 인서트 제조    [자체]  인서트팀  ✅ 완료
        ├── 공정 2: 본체 가공      [외주]  OO정밀    🔄 진행중
        ├── 공정 3: 조립 + 검사    [자체]  조립팀    ⏳ 대기
        ├── 공정 4: 케이블 작업    [자체]  조립팀    ⏳ 대기
        └── 공정 5: 최종검사+포장  [자체]  품질팀    ⏳ 대기
```

**개념**: 작업지시서는 "완제품 단위"로 1개만 만들고, 내부 공정은 체크리스트(Task)로 관리합니다.

### 옵션 B: 공정별 작업지시서 분리

```
생산요청서 (PR-001)
  └── 작업지시 그룹 (WOG-001, HXB13 100ea)
        ├── WO-001: 인서트 제조   [자체]  ✅ 완료
        ├── WO-002: 본체 가공     [외주]  🔄 진행중  → 발주서 PO-001 연결
        ├── WO-003: 조립 + 검사   [자체]  ⏳ 대기 (WO-001, WO-002 완료 대기)
        ├── WO-004: 케이블 작업   [자체]  ⏳ 대기 (WO-003 완료 대기)
        └── WO-005: 최종검사+포장 [자체]  ⏳ 대기 (WO-004 완료 대기)
```

**개념**: 공정마다 독립적인 작업지시서를 만들고, "작업지시 그룹"으로 묶어서 관리합니다.

## 3. 상세 비교

### 3.1 데이터 구조

#### 옵션 A
```
기존 work_order 테이블 유지
+ work_order_task 테이블에 필드 4개만 추가:
  - task_type (자체/외주/구매)
  - assigned_to (담당자)
  - due_date (예정일)
  - remarks (비고)
```

#### 옵션 B
```
신규 테이블: work_order_group
  - 완제품, 수량, 생산요청 연결, 그룹 상태

기존 work_order 테이블에 필드 추가:
  - work_order_group_id (소속 그룹)
  - process_type (자체/외주/구매)
  - process_name (공정명)
  - process_order (공정 순서)
  - depends_on_wo_ids (선행 WO 목록)
  - is_blocked (선행 미완료로 차단 여부)
```

---

### 3.2 작업지시서 생성 과정

#### 옵션 A (소요 시간: 약 1분)
1. "작업지시서 생성" 버튼 클릭
2. 제품 선택 + 수량 입력
3. BOM 자동 전개 (부품 목록 자동 생성)
4. 저장
5. 이후 공정 템플릿 자동 적용 (인서트→가공→조립→검사→포장)

#### 옵션 B (소요 시간: 약 5~10분)
1. "작업지시 그룹 생성" 버튼 클릭
2. 제품 선택 + 수량 입력
3. 공정 정의 (몇 단계? 각 이름?)
4. 각 공정이 자체/외주/구매 선택
5. BOM 부품을 공정별로 수동 배분
6. 공정 간 의존 관계 설정 (어떤 공정이 끝나야 다음 시작?)
7. 각 공정별 담당팀, 예정일 설정
8. 저장

---

### 3.3 부품(BOM) 관리

#### 옵션 A
- BOM 전체를 작업지시서 1개에 전개
- 전체 소요 부품을 한 번에 확인 가능
- 부품 출고도 한 번에 처리

#### 옵션 B
- BOM을 공정별로 쪼개서 각 WO에 수동 배분
- "이 부품은 어느 공정에서 쓰이나?" → 사람이 판단해야 함
- 하나의 부품이 여러 공정에 걸치면 배분 기준 애매
  - 예: 볼트를 조립 공정에 넣을지 케이블 공정에 넣을지?
- 부품 출고가 공정별로 분산

---

### 3.4 상태 관리

#### 옵션 A
```
관리 대상: 작업지시서 상태 1개 + 공정 체크 5개
  WO-001: IN_PROGRESS
    공정 1: ✅ 완료
    공정 2: 🔄 진행중
    공정 3: ⏳ 대기
    공정 4: ⏳ 대기
    공정 5: ⏳ 대기
```

#### 옵션 B
```
관리 대상: 그룹 상태 1개 + 개별 WO 상태 5개
  WOG-001: IN_PROGRESS
    WO-001: COMPLETED
    WO-002: IN_PROGRESS
    WO-003: BLOCKED (WO-001, WO-002 대기)
    WO-004: BLOCKED (WO-003 대기)
    WO-005: BLOCKED (WO-004 대기)

추가 로직:
  - WO 상태 변경 시 → 후속 WO의 blocked 여부 자동 재계산
  - 그룹 상태 = 개별 WO 상태의 종합 계산
  - 취소 시 → 후속 WO 전부 자동 차단?
  - 순환 의존성 방지 로직
```

---

### 3.5 외주 관리

#### 옵션 A
- 공정(Task)에 "외주" 표시
- 외주 업체명, 예정일 기록 가능
- 발주서(PO)와 직접 연결은 안 됨 (별도 관리)

#### 옵션 B
- 외주 공정이 독립 WO로 분리
- 해당 WO에 발주서(PO) 직접 연결 가능
- 외주 납기 지연 시 후속 WO 자동 차단

---

### 3.6 화면(UI) 복잡도

#### 옵션 A
```
작업지시서 목록:
  WO-001  HXB13 커넥터  100ea  작업중  [상세]

상세 화면:
  기본 정보 + 공정 체크리스트 + 부품 목록
```

#### 옵션 B
```
작업지시서 목록:
  [WOG-001] HXB13 커넥터 100ea (5개 공정)
    ├── WO-001  인서트 제조   자체  ✅ 완료
    ├── WO-002  본체 가공     외주  🔄 진행중
    ├── WO-003  조립 + 검사   자체  ⏳ 차단됨
    ├── WO-004  케이블 작업   자체  ⏳ 차단됨
    └── WO-005  최종검사+포장 자체  ⏳ 차단됨

  [WOG-002] HXB11 커넥터 50ea (2개 공정)
    ├── WO-006  인서트 제조   자체  ✅ 완료
    └── WO-007  조립 + 검사   자체  🔄 진행중

  WO-008  인서트 부품 500ea (독립, 재고 보충)

필요한 추가 화면:
  - 그룹 목록 뷰 (접기/펼치기)
  - 그룹 상세 뷰 (공정 흐름도)
  - 의존 관계 편집 UI
  - 그룹 진행률 표시
```

## 4. 종합 비교표

| 항목 | 옵션 A (Task 관리) | 옵션 B (WO 분리) |
|------|:---:|:---:|
| **DB 변경 규모** | 필드 4개 추가 | 테이블 1개 + 필드 6개 + 의존성 로직 |
| **개발 소요** | 2~3시간 | 3~5일 |
| **WO 생성 소요** | 1분 | 5~10분 |
| **BOM 관리** | 자동 (한 번에 전개) | 수동 배분 필요 |
| **재고 출고** | 한 번에 처리 | 공정별 분산 |
| **상태 관리** | 단순 (1+N 체크) | 복잡 (N개 상태 + 의존성) |
| **외주 관리** | Task에 표시 | WO 단위 분리 + PO 연결 가능 |
| **진행 파악** | 체크리스트로 한눈에 | 그룹 뷰 필요 |
| **확장성** | 중간 | 높음 |
| **유지보수** | 쉬움 | 의존성 버그 위험 |
| **학습 비용** | 낮음 | 높음 |
| **적합 규모** | 중소기업 (10~50명) | 대기업 MES (100명+) |

## 5. 적용 시나리오

### 5.1 옵션 A가 적합한 경우

- 생산팀 규모가 작고 (10명 내외) 팀 간 의사소통이 빠른 경우
- 공정별 독립적인 재고/출고 관리까지는 필요 없는 경우
- 빠른 도입이 필요한 경우 (2~3시간 내 구현)
- 시스템 사용 경험이 적은 팀에게 단순한 UX를 제공해야 하는 경우
- "어떤 공정이 끝났고, 다음은 뭔지" 정도의 추적이면 충분한 경우

### 5.2 옵션 B가 적합한 경우

- 공정별로 완전히 다른 팀/외주업체가 관리하는 경우
- 공정별 부품 출고/재고를 독립적으로 추적해야 하는 경우
- 외주 비중이 높아서 발주서와 작업지시를 연결해야 하는 경우
- 생산 규모가 크고 체계적인 공정 관리가 필수인 경우
- MES(제조실행시스템) 수준의 관리가 필요한 경우

## 6. 권장안

### 단계적 접근 (추천)

| 단계 | 시기 | 내용 |
|------|------|------|
| **Phase 1** | 즉시 | **옵션 A로 운영 시작** — Task 필드 보강 (자체/외주 구분, 담당자, 예정일) |
| **Phase 2** | 운영 1~2개월 후 | 실사용 데이터 기반으로 **옵션 B 필요성 재평가** |
| **Phase 3** | 필요 시 | 옵션 B로 확장 (옵션 A의 Task 데이터는 그대로 활용 가능) |

### 근거

1. **옵션 A에서 B로의 전환은 가능**하지만, **B에서 A로 돌아오기는 어려움**
2. 운영 경험 없이 복잡한 구조를 먼저 만들면 **사용 자체를 기피**할 위험
3. 옵션 A로 운영하면서 **"Task로는 부족한 상황"**이 실제로 발생하는지 확인 후 결정
4. 옵션 A의 Task 데이터는 옵션 B 전환 시 **마이그레이션 가능** (Task → 개별 WO로 변환)

---

## 7. 옵션 A 즉시 구현 시 추가 보강 사항

현재 `WorkOrderTask` 모델에 4개 필드를 추가하면 대부분의 실무 요구를 커버할 수 있습니다:

| 추가 필드 | 용도 | 예시 |
|---------|------|------|
| `task_type` | 자체/외주/구매 구분 | INTERNAL, OUTSOURCE, PURCHASE |
| `assigned_to` | 담당자명 | 김OO, OO정밀(외주) |
| `due_date` | 공정 예정일 | 2026-04-15 |
| `remarks` | 공정별 비고 | "외주 납기 확인 필요" |

이 보강만으로:
- 공정별 자체/외주 구분 ✅
- 공정별 담당자 지정 ✅
- 공정별 납기 관리 ✅
- 공정별 진행 상황 추적 ✅
- 전체 진행률 한눈에 파악 ✅
